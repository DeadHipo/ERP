Ничего не хранится как начисление. Каждый ответ пересчитывается из сырых строк отчётов и текущих справочников. Выплата замораживает снимок расчёта.

источники денег справочники (модули) фасад: расчёт B — чужое, подтверждено C — ждёт документа наша доля API и экраны

1. Откуда берутся данные

Believe (мастер)

Месячные CSV отчёты дистрибьютора. Загружаются через API, строки как есть, ничего не склеивается.

B17 (паблишинг)

Квартальные xlsx. Payee = rights-holder, авторы = songwriters.

Контракты, Annex 14, 0to8 Main.xlsx

Прочитаны один раз загрузчиком scripts/mvp/load.ts и превращены в справочники: сплиты, участия, правила лейблов, авансы, история выплат (факт).
→

sources

Реестр файлов в PostgreSQL, строки в ClickHouse believe.rows. Считаются только файлы со статусом loaded.

publishing

Строки B17, писатели ↔ владельцы, условия (terms) по типу операции.

owners · labels · splits · settlements

PostgreSQL, одна схема на модуль, без внешних ключей между ними.
→

facade

Единственное место, где модули встречаются. Один snapshot на запрос, чистые функции слоёв, ничего не пишет кроме выплат и операций.

API /api/v1 · React

Очередь C, сигналы, треки, артисты, владельцы, сплиты, участия, лейблы, документы, источники, операции.

Приватные данные (имена авторов B17, псевдонимы участников) живут только в локальном архиве и в data/mvp-load/ (git-ignored). В коде, тестах и документации их нет.

3. Расчёт одной единицы: шесть слоёв

Единица = ISRC + UPC + месяц отчёта + месяц продаж + строка лейбла, сумма net. Для каждой единицы фасад прогоняет фиксированную цепочку (facade/layers/index.ts, порядок записан в одном месте). Пример справа: net = 100.

слой
пример, net 100
1
Лейбл записистрока лейбла → алиас → наш лейбл или саблейбл с правилом на месяц. Неизвестная строка: наша доля уходит в C label_unmapped, остальное считается.
"Echo8 Records" → саблейбл Echo8 Records правило: 50 % доли лейбла → псевдоним саблейбла
2
Периметрнет ISRC → C no_isrc; пары ISRC+UPC нет в треках → C unknown_pair. Цепочка останавливается.
пара известна → идём дальше
3
Сверху (off the top)участия с базой net: ремиксер, фичеринг. scaledNet = net − Σ top. Сумма % > 100 отвергается на входе.
ремиксер 10 % от net = 10.00 scaledNet = 90.00
4
Сплитстроки сплита на месяц отчёта × scaledNet. Доля лейбла = остаток вычитанием. Нет сплита — всё в доле лейбла, статус no_split.
артист A 50 % = 45.00 доля лейбла = 90 − 45 = 45.00
5
Вырезки (carves)в фиксированном порядке: pool → artist_share → label_share → саблейбл. Одна общая база на вид, порядок участий внутри вида не влияет. Вырезка больше корзины берёт корзину, недостача — сигнал unfunded.
продюсер 20 % из доли A = 9.00 (A → 36.00) саблейбл 50 % из доли лейбла = 22.50 наша доля = 22.50
6
Категориядля каждого получателя, первая причина побеждает: assumption → документ не одобрен (split_unconfirmed / rule_unconfirmed) → псевдоним без владельца → владелец не подтверждён → иначе B.
ремиксер 10.00 B A 36.00 B продюсер 9.00 C rule_unconfirmed саблейбл 22.50 B мы 22.50 ours

Точность: каждое произведение квантуется до 12 знаков сразу после умножения, каждый остаток получается вычитанием, остаток пропорции уходит на наибольшую сумму. Поэтому Σ получателей + доля лейбла = net после любого слоя, и ни одна сумма не меняет знак (D-127, D-130). Это проверяет случайный seeded-тест и 46 золотых кейсов.

1 · Части писателей

Строка идёт равными частями нашим сопоставленным писателям из songwriters; если ни одного — держателю (rights-holder).

2 · Доля автора

Условия по владельцу, дате и типу операции (Performance, Mechanical…). По умолчанию 50 %. Остальное — лейблу.
→

3 · Категория

writer_unmapped, owner_unconfirmed, publishing_terms_unconfirmed, иначе B.

5. Сходимость: A = B + C + наше

B 68.50
C 9.00
наше 22.50

A = 100.00 — пример из §3. Проверяется на каждый источник, счёт и месяц; наша доля берётся из состояния слоёв, а не как A − B − C, поэтому потерянные деньги видны как расхождение ≠ 0. На реальных данных 2024-01 … 2026-08 расхождение 0 во всех 52 строках.

6. Баланс владельца и выплата

payable = earned (B) − recouped − выплаты с подтверждением + возвраты + кредиты

balance.ts

  • earned и waiting — суммы B и C владельца по всем псевдонимам, мастер + паблишинг, отдельно по лейблу записи
  • recoup (layers/recoup.ts): аванс гасится доходом в своём scope, только если его документ одобрен; сам аванс не вычитается
  • отрицательный payable хранится, на экране 0 с пометкой
→

Кнопка «Выплатить»

  • единственный путь оплаты заработанного (createPayout); endpoint операций обычную выплату отвергает
  • платит весь payable, округлённый вниз до центов
  • записывает снимок: по артистам, хэши файлов — того самого расчёта
  • платёжный сервис — заглушка
