# ADR-002: Строки отчёта без ISRC — ручной разбор в модуле Believe (ОТМЕНЁН)

Статус: **отменён 2026-10-30** (было: принято 2026-10-29). Вариант ручного разбора убран полностью; для строк без ISRC остаётся единственный вариант, прямое начисление артисту через взаиморасчёты (M10), он оставлен открытым вопросом, см. [06_модуль_источников.md](../06_модуль_источников.md), вопрос 2. Текст ниже сохранён только как история.

## Контекст

В отчётах Believe есть строки без ISRC и без названия трека: продажи целых релизов в iTunes (1 364 строки из 62 млн, только UPC). Подробности: [03_проверка_отчётов_believe.md](../03_проверка_отчётов_believe.md). Рингтоны ISRC имеют.

## Решение

- Такие строки **автоматически не привязываются**. Они попадают в **список ручной проверки**.
- Оператор вручную указывает нужные ISRC и разрешает («резолвит») строку.
- Это происходит **в модуле Believe**, а не в модуле владения треком (модуль 1). Модуль 1 о таких строках ничего не знает.
- После разбора ISRC (вместе с UPC) попадает в **список треков автора** в модуле 1 обычным путём.
- Принятое решение по строке запоминается, чтобы такая же ситуация не разбиралась повторно.

## Почему

- Автоматическая раскладка по трекам релиза была бы догадкой о деньгах; ошибки в выплатах дороже ручной работы над небольшим числом строк.
- Модуль 1 остаётся чистым: в нём только подтверждённые ключи ISRC + UPC.

## Последствия

- Модулю Believe нужны очередь ручной проверки и хранилище решений (по какому ключу строки запоминаем решение — определить при проектировании модуля).
- Нужно описать интерфейс «Believe → модуль 1»: как разобранный ISRC + UPC создаёт трек в списке автора, если такой пары ещё нет. Новая запись по общему правилу создаётся «незакрытой» (без подтверждения договором).
