# Принципы

Статус: принято 2026-10-29 (по обсуждению; детали в ADR).

1. **Ключ системы — трек. Внутренний id генерируем сами; уникальна пара ISRC + UPC.** ISRC трека не меняется между релизами. → [ADR-001](решения/ADR-001-владение-треком.md)
2. **Цепочка владения:** Владелец → Артист → Трек. Релиз — необязательная надстройка.
3. **Артист принадлежит ровно одному владельцу.** Если один псевдоним ведут два владельца, это две отдельные записи артиста.
4. **Связь «артист — трек» хранится в модуле 1,** вводится нами и нужна, чтобы знать, к какому артисту принадлежит трек (без разбора имён из отчётов). Получателей определяет только сплит по ISRC (решено 2026-10-31).
5. **MC — это тоже артист** со своим владельцем, отдельной модели нет. Выплаты ему идут через сплиты (позже).
6. **Всё подтверждается договором.** Без договора сущность можно создать, но она «незакрыта» и требует подтверждения. Статус только помечает; перед выплатой отдельная проверка документов (следующий шаг).
7. **Договор заключается с владельцем (лейблом); основа + приложения.** Основа: человек и его псевдонимы. Приложения: сплиты (позже).
8. **Трек можно создать до выгрузки без ISRC**; ISRC дописывается позже.
10. **ISRC — ключ трека; названия — справочная информация.** Разные версии трека — разные треки с разными ISRC (решение 2026-10-30). Запись трека идентифицируется парой ISRC + UPC, а расчёт и сплит на трек ведутся по ISRC. Получатели определяются только сплитами, имена исполнителей из отчётов не используются (решено 2026-10-30).
9. **Роль `owner` / `feat` / `mc` на связи не нужна** (решено 2026-10-30): получатели берутся из сплита.
