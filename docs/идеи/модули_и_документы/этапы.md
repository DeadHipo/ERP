**Поправки после адвоката простоты (цикл 4).** Этап 3 не делается «впрок»: срок действия у алиаса нужен только с первой
переразметкой, поэтому он стартует вместе с ней. Перенос выгрузки релизов в `sources` (Р15) из этапа 4 убран: по
метрикам он нейтрален и ломает устройство модуля `sources`; делать только попутно. Единая очередь (Р23) — отдельная
цель, а не шаг этапа Э; в чистку входит только удаление статичной страницы «Вопросы». Результат по ступеням: после
этапов 1–2 таблиц 43, после этапа 4 — 42, после этапа 5 — 37.

**Поправки после приёмки панелью (цикл П2).**
- *Дампы.* Перед каждым `DROP` дамп таблицы кладётся в архив данных с хешем файла, а факт удаления и хеш пишутся в
  `audit` (просьба внешнего аудитора).
- *Карта «куда добавить источник» (Р24)* — страница в `docs/agents/` из трёх шагов вокруг `SourceUnit`; пишется в цели
  этапа 1. Тест «числа до и после» — это общая проверка каждого этапа, отдельного теста не вводим.
- *Этап 1, алиасы паблишинга.* До удаления — замер: сколько авторов и песен имеют больше одного написания (сегодня 0).
  Поведение не меняется: и сегодня другое написание создаёт нового автора, которого человек связывает с владельцем
  (`modules/pubv2/CLAUDE.md`); таблицы алиасов хранят только копию имени.
- *Этап 2, id договора.* Старые ссылки на договор должны открываться: таблица соответствия «id договора → id
  документа» остаётся в D-записи, поиск по номеру договора работает как раньше (`contract_number`).
- *Этап 3, переразметка.* Перед словом владельца ему показывают расчёт «до и после» в деньгах: сверка и балансы
  затронутых владельцев по месяцам перехода (вывод сравнения, а не новый экран). Партнёра саблейбла предупреждают
  заранее.
- *Этап 5, подсказки автора.* До удаления `old_map` — сравнить рекомендации «автор → владелец» с ним и без него для
  всех 34 авторов; расхождения записать в D-запись.

## Общее для всех этапов

**Готово, когда** (как в `CLAUDE.md`): `npm run typecheck` и `npm run lint` чистые, `REQUIRE_STACK=1 npm test`
проходит, `npm run build:client` собирается, `npm run e2e` зелёный (если тронут фронт), D-запись и строка индекса
есть, проверка «деньги не изменились» пройдена.

**Проверка «деньги не изменились».** Две части.

1. Тесты: `tests/golden.test.ts` (85 случаев) и `tests/layers/exactness.test.ts` проходят без правки ожидаемых чисел;
   `git diff` по закрытым зонам (`calculation.ts`, `facade/layers/*`, `owner-scope.ts`, `balance.ts`) пуст.
2. Теневой прогон на живой базе, только чтение, по образцу `packages/backend/scripts/pubv2/shadow.ts`. Тот скрипт
   считает `calculate()` двумя способами в одном процессе и печатает рядом суммы по кварталу, по причине C и по
   владельцу. Для этапа без переключателя то же делается снимками «до» (перед миграцией) и «после» (сразу после неё).
   Сравнивать байт в байт:
   - `calculate()`: суммы A, B, C и «наше» по месяцу, книге и причине C;
   - `reconcile()` по каждому источнику, аккаунту и месяцу;
   - балансы всех владельцев: `payable`, `payableShown`, позиции по псевдонимам
     (`scripts/check-label-books.ts --dump` до и `--compare` после);
   - ведомость `payroll` за каждый месяц (json);
   - состояние среза «Кабинет 15.10» (`GET /settlements/cuts/:id/state`);
   - `scripts/check-owner-scope.ts` (баланс по охвату = полный) и `scripts/check-label-books.ts` (книги складываются
     в баланс): расхождений 0.

   Ожидаемый результат — пустая разница. Любая строка разницы останавливает этап.

**Откат.** Где есть переключатель — переключатель. Для `DROP` — дамп таблицы в архив данных (D-093) до миграции и
обратная миграция, которая создаёт таблицу и заливает дамп. Для кода — `git revert` коммита этапа.

- Реестр сторон: «золотая запись» уже есть — владелец, `merged_into` и `ownerResolver`.
- Журнал событий одной таблицей: второе место правды; лента собирается из `audit` и таблиц решений.
- Деление `owners` на три модуля: +2 модуля, +4 межмодульные связи и открытый `calculation.ts`.
- Модуль документов с провайдерами: файл в ERP не хранится, провайдер уже виден по префиксу `file_ref`.
- «Точка чтения» на каждый модуль: +10 файлов, связность не падает.
- Разделение слитых (unmerge): слияний за всё время 2, снимки хранят старые id.
- Уникальность имён: 20 групп одноимённых законны.
- Автослияние: решает человек, система только подсказывает.
- Автоплатежи: платёжный сервис вне рамок проекта.
