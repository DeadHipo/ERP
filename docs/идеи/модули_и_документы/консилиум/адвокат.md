## Проверка «числа не меняются»

- **Р6 шаг 1.** Пока у всех 34 алиасов открытый период, числа не меняются. Но ключ таблицы `PRIMARY KEY (org_id,
  alias_norm)` (pg_constraint) не даёт строке иметь два периода. Нужен новый ключ и проверка «периоды не
  пересекаются», то есть новый инвариант, а не «две колонки». Охват владельца (`owner-scope.ts:61–64`) берёт алиасы
  без даты: получится надмножество, это безопасно.
- **Р8.** На живой базе числа не меняются (v2 включён). Но `publishing.pub_terms` содержит **1 типизированное условие
  одного владельца** (`operation_type is not null`). Это ровно ⚠ D-187 («the typed term of one owner does not apply under
  v2»). `DROP` пяти таблиц навсегда закрепляет ответ на этот ⚠. В6 должен назвать D-187 прямо.
- **Р10 `artist_tracks`.** Подтверждаю: из 15 493 пар без покрытия сплитами и участиями 0, с учётом слияний тоже 0.
  Деньги таблицу не читают: только `owner-view.ts:99` и `artist-view.ts:189` (показ), `track-artists.ts`.
- **Р10 алиасы pubv2.** Алиас создаётся только вместе с новой сущностью (`modules/pubv2/service.ts:61–87`), пути
  слияния нет, авторов с двумя алиасами 0. Удаление безопасно.
- **Р11.** Договоров на документ больше одного: 0. Порог задан: 0. Слияние 1:1, чисел не меняет. Но запись договора —
  это ⚠ **D-018** («Contract record without personal data … fields will be added with access rights»). Р11 решает,
  где лягут будущие поля лица (на `documents`). Это надо назвать в В4.
- **Р13.** Каталог не входит в деньги (D-172, `catalog.test.ts`), ПК4 даёт 0 расхождений. Числа не меняются, но каждая
  страница каталога медленнее на 0,35–0,45 с.
- **Р15.** Деньги не затронуты.
- **Р21.** Сегодня у слитых владельцев payees 0, holds 0, answers 0. Ответы допуска для уже слитых не меняются.
  Правило действует только для будущих слияний.

## Где итог усложнил

1. **Р23 «одна очередь»** — новая модель чтения с пометками «блокирует / информация», «чьё действие», пакетными
   действиями (новые пути записи), пунктами «итог импорта провайдера» и «849 ников». Меню становится короче на 3 пункта,
   но сама очередь сложнее двух страниц, которые она заменяет. Это функция, а не упрощение.
2. **Р6 шаг 1** — механизм под будущую потребность: данных под него 0 (все периоды открыты), а потребитель (Р7,
   переразметки) ждёт В1. Решение «Ahh Music = 0to8» владелец уже принял 2026-11-02. Сегодня шаг добавляет 2 колонки,
   новый ключ и новое правило без единого применения.
3. **Р16 «провайдер = префикс `file_ref`»** — соглашение о строке вместо колонки. Его не проверяет CHECK, в данных оно
   уже нарушено (10 других значений), а метрика красных связей его не считает. «0 новых таблиц» здесь куплено скрытой
   строковой связью.
4. **Р11** — −1 таблица, но +3 колонки на `documents`, которые нужны 818 строкам из 1 447, а флаг `is_contract` сам
   становится понятием. Цена — смена id договора в 9 файлах фронта. Чистый выигрыш маленький.
5. **Р15** — по метрикам нейтрально (это признаёт сам итог), DDL переноса схемы есть. Модуль `sources` по CLAUDE.md
   устроен без `schema.ts` и `repository.ts` (`registry.ts`, `columnar.ts`), так что перенос ломает его устройство ради
   «правильной полки».
6. **Р9** — v1 уходит таблицами, но остаётся словарём: адаптер отдаёт `writerNorm`, `resolution: 'manual'|'unmapped'`,
   `role: 'holder'` и типизированный слот `operationType` (`pubv2-source.ts`). Понятия v1 переживают v1 внутри закрытой
   зоны.
7. **Р20, Р25, Р26, Р18** добавляют работу внутри «упрощения»: новые признаки дубля, обязательный audit для всех
   скриптов, «выписка артиста — сразу после чистки», «маршруты мимо фасада — потом».

## Что можно было удалить, но совет оставил

- `meaning` — временный псевдоним `kind` (D-173). Он жив в API, в общих схемах и на фронте (`api/operations.ts`,
  `shared/src/api-schemas.ts`, `OperationActions.tsx`). Совет его не назвал.
- Мёртвая ветка D-087 в `layers/writer-parts.ts` — отложена «до отдельной D-записи» без срока.
- `mergeArtists` — мёртвый код, вопрос передан владельцу (Р22). Дешевле удалить: вернуть можно из git.
- Мусорные документы в живой базе (`file_ref` = `123`, `123123`, `acceptance/replay-…`) — это кандидаты на чистку
  данных (только вопрос, не правка).

Совет не удаляет ничего, чем пользуются. Ближе всего к потере — DROP v1 вместе с типизированным условием (⚠ D-187).
