## 4. Где документ влияет на деньги

Что деньги читают из документа: ТОЛЬКО две вещи — (а) статус `approved` (из `file_ref`, `requires_approval`, `approved_at`), (б) `kind` (одно сравнение с `assumption`), плюс `label_id` для вопроса «подтверждён ли владелец под лейблом L» и `payout_threshold_cents` договора для порога. Не читают: `title`, `owner_id` документа, `approved_by`, `upload_deadline`, `migration`, `created_at`, `contract_artists`, `number`, содержимое файла и префикс `file_ref`.

Цепочка:
1. `be/facade/calculation.ts:160-161, 183` читает `owners.confirmedOwnerIds()`, `owners.confirmedContracts()` и `owners.documentInfo(docIds)`; `docIds` = документы сплитов, правил, условий паблишинга (`calculation.ts:174-178`) + документы операций (`extraDocumentIds`, собирает `facade/context.ts:~140 opDocIds`). `calculation.ts:201-203` строит `documentStatus` и `documentKind`; `:358` `confirmedOwnersUnder(label)` по `labelId` документа договора.
2. `be/modules/owners/service.ts:107-114, 160-185` — единственное правило статуса и «договор подтверждает» (документ approved, и при `labelId` документ того лейбла или без лейбла).
3. `be/facade/layers/categorise.ts:17-25` (мастер): kind `assumption` → C `assumption`; статус не approved → C `split_unconfirmed` (строка) / `rule_unconfirmed` (правило); владельца нет в `confirmedOwners` → C `owner_unconfirmed`. Документ строки берётся как `sh.documentId ?? sp.documentId` (`layers/split.ts:23`); для вырезов — `layers/carve.ts:48,173`, `layers/off-the-top.ts:52`.
4. `be/facade/layers/publishing-categorise.ts:15-17` (паблишинг): `owner_unconfirmed`, затем `publishing_terms_unconfirmed` если условий нет (`defaultTerms`) или `documentStatus(termsDocumentId) !== 'approved'`; `author-share.ts:33` берёт `termsDocumentId`. В v2 условия по ISRC при конфликте получают `documentId: null` (`facade/pubv2-source.ts:68`) — статус `missing`, деньги ждут.
5. `be/facade/balance.ts:254-265` (`classifyOperation`): исходящая операция считается, если `payment_proof_id` approved (кроме `migration`); для `advance` и `buyout` ещё и основание approved; входящие (deduction, credit, forgiveness, writeoff, adjustment, return) — если approved `document_id`. `balance.ts:510-511` `confirmed` / `confirmedAny` (вход шлюза); `balance.ts:1043-1050` `blockingPayouts`; `balance.ts:1222` учёт платёжных документов в `paid`.
6. `be/facade/payout-gate.ts:51-62` — порядок: `owner_not_confirmed`, `no_contract_for_label` (из статуса договора), … `below_threshold`, … `payout_blocked` (из `blockingPayoutsOf`). `be/facade/context.ts:120-138` `blockingPayoutsOf`: выплата/аванс без approved payment_proof или отложенный блокирует новые. `be/facade/payouts.ts:142-160` то же для advance (проверки `isOwnerConfirmed`, `isOwnerConfirmedUnder`, `blockingPayoutsOf`).
7. `be/facade/admission.ts:29-41` `contractThresholds` и `context.ts:271` читают `approvedContracts()`: порог из `contracts.payout_threshold_cents` выбранного договора (свой лейбл раньше «любого», потом самое новое одобрение).
8. Только показ (деньги не меняют): `aggregates.ts:356`, `queue.ts:265` (`documentStatus` в строке очереди), `onboarding.ts:75`.

Закрытая зона: все места 1, 3, 4 лежат в `calculation.ts` и `layers/*`; `owners/service.ts` и `balance.ts:254-265` — граница закрытой зоны (математика `balance.ts`).
