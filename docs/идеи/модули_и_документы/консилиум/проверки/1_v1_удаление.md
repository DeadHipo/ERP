4. **Вердикт: подтверждено с оговорками.**
   - (а) Закрытые зоны действительно 0 строк. Но тип `PublishingService` пришлось написать заново, как интерфейс в модуле: раньше это был `ReturnType` сервиса v1. Модуль теперь объявляет форму, которую реализует фасад (`pubv2-source.ts`), а `parseSongwriters` лежит в модуле только ради импорта из слоя. На спор «0 против 2 строк» это не влияет, но это архитектурная натяжка.
   - (б) «typecheck чист» верно только для `src`. По бэкенду целиком — нет, пока не переписаны тесты и скрипты.
   - (в) В закрытой зоне остаётся **мёртвый код**. Под v2 у строки всегда `songwriters: null`, а `resolution` бывает только `manual` или `unmapped`. Поэтому в `writer-parts.ts` ветки «равные части наших авторов» (D-087) и «ambiguous» не выполняются никогда, работает только ветка держателя. Типизированные условия `author-share.ts` **не мертвы**: их использует D-192 (ключ `isrc:<id>` / `isrc-conflict:…`). Условия по типу операции D-128 (Mechanical/Synchronization) исчезают.
   - (г) Golden-случаи:
     - G43 (i–iii), G55 и G59 (5 падений): одна строка держателя, условие 50 % с документом, 60 → 30. Их можно построить через v2 **без изменения ожидаемых чисел**: файл-сводка, `linkSongwriter`, `setPublishingTerm`. Нужен помощник записи сводки вместо `writeB17` и перенос условия в `links`.
     - G26a–e (5 падений) **теряют смысл**:
       - G26a, G26b и G26c проверяют D-087 и D-128, которых v2 не знает.
       - G26d переносится: связь есть, условия нет → 50 % по умолчанию, `publishing_terms_unconfirmed`.
       - Итоговые числа G26e (A 400, B 170, C 50, ours 180) станут другими.
     - Если G26a–c убрать, D-087 в слое останется без живого теста, кроме юнит-тестов `tests/layers/`.
