## 4. Вердикт
**Подтверждено с оговорками.** Для денег — 0 файлов вне модуля. Оговорки касаются читателей «без даты», не денег:
1. **owner-scope.ts** берёт строки алиасов любых периодов у лейблов с правилом получателя и все ISRC с такой строкой за все месяцы: охват остаётся надмножеством (может стать шире, но не уже); scope.test проходит. Правка не нужна.
2. **ads.ts / calculation.ts:300-331**: расчёт выбирает только строку ISRC за месяц расхода, лейбл решает `ctx.labelOf(labelString, monthStart(ad.month))` — дата передаётся, работает без правок.
3. Прочие читатели: `reports.ts labelUnmapped` и `queue.ts` (`label_unmapped`) берут категорию юнита, посчитанную с датой — верно. `onboarding.ts` строит множество строк всех периодов без даты: строка, ставшая алиасом только с месяца M, засчитается «сопоставленной» и для файлов до M (ложное «готово» в чек-листе; деньги при этом честно в C `label_unmapped`) — нужна проверка «строка × месяц файла» (небольшая правка, не закрытая зона). `sources.isrcsOfLabelAliases` служит только охвату — надмножество годится. `aggregates.ts` алиасов не читает. Python-экстрактор `scripts/mvp/extract-main-ads.py` читает `alias_norm → label_id` словарём: при нескольких периодах возьмёт произвольную строку — нужен фильтр по периоду.
4. **Ключ**: `(org_id, alias_norm)` больше не уникален; заменён на EXCLUDE по периоду (как `label_rules_no_overlap`), сервис заранее отвечает 409 `alias_taken`. Разрыв между периодами строки даёт `label_unmapped` в эти месяцы (честно, но при закрытии стоит предупреждать).
