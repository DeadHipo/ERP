# Проверка 3_договор_в_документ: owners.contracts сливается в owners.documents с флагом is_contract без изменения множеств и чисел

## 1. Утверждение и спор

Утверждение: таблицу `owners.contracts` можно влить в `owners.documents`. Колонки `number` и `payout_threshold_cents` переезжают в документ, договор становится документом с признаком договора, а `confirmedOwnerIds` / `confirmedContracts` / `approvedContracts` и все числа остаются прежними.

Спор о том, что считать признаком договора:
- архитектор: признак — заполненные колонки договора;
- минималист, интеграции и менеджер: признак — вид из `CONTRACT_DOCUMENT_KINDS` вместе с `owner_id`.

## 4. Вердикт

**Подтверждено с оговорками.**

1. Утверждение верно только при явном флаге `is_contract`. Если признак — вид документа плюс владелец, подтверждённым становится 1 владелец, и деньги по 247 строкам сплитов уходят из C в B. Чтобы этого избежать, 2 документа надо перевести в вид `other`. Кроме того, ещё 3 документа появятся в колонке договоров ведомости и в списках: на деньги это не влияет, но вывод меняется.
2. Вариант «по виду» даёт меньше понятий (нет флага), но требует правки данных: 2 документа обязательно, 5 — для согласованных списков. К тому же любой будущий утверждённый `contract` с владельцем станет договором неявно, а не через `createContract`.
   Вариант «флаг» обходится одной колонкой и ничего не меняет в данных. Рекомендую флаг `is_contract` с nullable `contract_number` и порогом в той же строке документа.
3. id договора становится id документа. `PATCH /contracts/:id` и поле `id` в ответах получат другие значения для всех 818 договоров. Ссылок в аудите нет.
4. Два договора на одном документе теперь невозможны. В живой базе таких 0, ни один тест на это не опирается.
5. `createdAt` договора теперь равен дате документа: время создания строки договора теряется.
