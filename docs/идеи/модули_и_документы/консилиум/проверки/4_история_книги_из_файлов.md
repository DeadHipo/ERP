1. **Утверждение.** История лейбла ISRC (23 635 строк, все `files`, операторских 0) выводится на чтении из `public.source_files` + ClickHouse чистой `deriveIsrc`, и читатели (GET /tracks/:isrc/labels, `trackCatalog` с `catalog=current`, `onboarding.ts`, сигналы `catalogSignals`) дают те же ответы за приемлемое время. Спор: минималист и интеграции («удалить») против архитектора и менеджера («оставить, пока не доказаны скорость и равенство»).

2. **Что сделано в копии** (worktree на `feature/fable-003`, не закоммичено). `git diff --stat`: 4 файла, +39 / −7 (`catalog.ts` +35: функция `historyFromFiles(sources, isrcs?)`; `aggregates.ts`, `onboarding.ts`, `reports.ts`, `history()` и `openCatalog()` читают её вместо `owners.trackLabels.list()`). Плюс два одноразовых скрипта только для чтения (`scripts/bench-catalog*.ts`), запускались с `default_transaction_read_only=on`.

4. **Вердикт: подтверждено с оговорками.**
   - Равенство полное (0 расхождений), деньги не затронуты.
   - Цена: около +0,35–0,45 с на каждый читатель «всей истории» (+30–40 % к странице каталога и чек-листу). Карточка трека остаётся в пределах 25 мс. Это заметно, но не мешает работать. Кеш (вне рамок проекта) не нужен: страница остаётся в пределах 1,1–1,8 с, а сигналы и так считают весь `calculate()`. Плюс: история больше не устаревает между загрузкой отчёта и запуском `derive-track-labels.ts`.
   - Главная оговорка (D-172): **операторские интервалы** (`POST /tracks/:isrc/label`, форма `SetTrackLabelForm` в `TrackLabelsDialog` на P6 и в диалоге сигналов P21) **при удалении таблицы исчезают**. Сейчас в живой базе их 0, но возможность есть в API и в UI. Варианта два:
     - (а) убрать операцию и форму решением владельца;
     - (б) хранить поправки где-то ещё, например в маленькой таблице только операторских строк. Тогда таблица фактически остаётся, только без строк `files`, и `cutByOperator` применяется на чтении.

     Без одного из этих решений удалять таблицу нельзя: набросок молча теряет поправки оператора.
   - Чтение одного лейбла нельзя сузить списком ISRC: нужен подзапрос в ClickHouse или фильтр по всей истории.
