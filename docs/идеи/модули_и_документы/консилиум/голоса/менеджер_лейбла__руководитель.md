# менеджер_лейбла / руководитель

1. **Кто я и что делаю каждый месяц.** Веду команду менеджеров лейбла (2 170 псевдонимов, 1 328 владельцев, 8 235 релизов в базе), отвечаю перед владельцем за дубли, чужие сплиты и неподтверждённые деньги.

2. **Пять моих сценариев.**
- **Завести артиста без дубля.** Ввожу псевдоним, при желании владельца. Работает частично: `POST /artists` отвечает 409 `possible_duplicate`, диалог «тот же / новый» (`pages/reference/artists/CreateArtistDialog.tsx`, `DuplicateDialog`). Проверка идёт по нормализованному псевдониму (`GET /artists/duplicates`, operations.ts:509). Тот же человек под другим ником, автор B17 с похожим именем, ISRC в чужом сплите не подсказываются: не нашёл.
- **Завести релиз.** Релиз в системе не создаётся, он приходит из экспорта Believe: `POST /releases/preview` и `/preview/apply`, `ReleaseImportDialog.tsx`, `GET /releases/registry`. Завести заранее, до выхода отчёта, не могу: не нашёл.
- **Завести сплит.** Работает: `POST /splits`, `/splits/change`, импорт шаблоном с предпросмотром (`POST /splits/import?dryRun=1`, `facade/split-import.ts`), «100 % лейбл» пустой строкой. Строки без документа ждут в `split_unconfirmed`, их подтверждает `POST /splits/:id/confirm`.
- **Привязать документ и владельца.** Владельца назначаю (`POST /artists/:id/owner`), договор создаётся (`POST /contracts`). Но файл договора из PandaDoc или final_index к строке сплита сам не приходит: связываю руками, вкладка `DocumentsTab.tsx`.
- **Проверить готовность лейбла и своих менеджеров.** Чек-лист подключения (`GET /onboarding`, `pages/work/onboarding`): сплит у каждого ISRC, владелец у каждого псевдонима, документы. Работает. Кто из менеджеров что завёл и ошибся, вижу только через `GET /audit` (операторский след), без «моих задач».

3. **Три боли сегодня.**
- **Дубль ловится только по написанию.** Одного человека под двумя никами и автора паблишинга с тем же именем система не показывает: решаю по памяти и по звонку оператору.
- **У 75 псевдонимов нет ни одной строки сплита, у 849 нет владельца.** Это ручной хвост: каждый такой артист потом ждёт в C, а список лежит в чек-листе и сигналах, не в моей очереди.
- **Лейбл трека держится на строке импринта** (алиасы без периода). Совместные импринты («0to8 x …») разнесены непоследовательно: за ошибку отвечаю я, а исправить могу только через оператора.

4. **Что нельзя ломать.** Расчёт и цифры: A = B + C + наше. Подтверждение документом: без него деньги в C с причиной. Диалог «тот же или новый» с явным выбором. Предпросмотр импорта сплитов и «всё или ничего». Правило «псевдоним: либо строка, либо участие». Изоляцию по лейблам (менеджер не видит деньги всей организации, чужой лейбл читается как 404). Операторский след у каждой записи.

5. **Что я сочту усложнением.**
- Ещё один реестр «кто есть кто» рядом с владельцами, артистами и авторами: нужен один путь, а не четвёртое место поиска.
- Обязательный шаг «создай сущность в одном модуле, потом свяжи в другом» для обычного нового артиста.
- Больше страниц и вкладок. Сейчас 21 страница, мне нужна одна точка «завести» и одна «разобрать».
- Новые слова вместо понятных: псевдоним, владелец, сплит, документ.
- Подтверждения, которые вызывают на каждую строку отдельно, когда у релиза их десятки.

6. **Чего не хватает продукту.** Единой карточки «кто это» с подсказкой совпадений (ник, человек, автор B17, ISRC в чужом сплите), потому что только она отвечает на мой главный вопрос без звонка оператору; плюс рабочий список менеджера «что мне доделать» (артисты без владельца, строки без документа), чтобы я управлял командой, а не искал по страницам.
