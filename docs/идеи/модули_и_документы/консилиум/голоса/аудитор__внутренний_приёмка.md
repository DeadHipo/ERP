# аудитор / внутренний: приёмка

**Вердикт:** принимаю с замечанием

**Что из моего первого голоса закрыто**
- Р25: скриптовые загрузки пишут в тот же audit (сегодня идут мимо). Это моя главная просьба, и она закрыта.
- Р1, Р5, Р21, Р23: журнала-таблицы нет, второго места правды нет, срез остаётся неизменяемым снимком, снимки хранят старые id. Сломанного у меня нет.
- Р11 и Р17: договор становится одним документом, статус подписи не хранится, значит нет второго источника «кто подтверждён».

**Что не закрыто или отложено**
- «Было / стало» по значениям. Р25 называет ленту «было / стало», но audit хранит id и суммы. Итог не говорит, что в audit добавляется предыдущее значение, так что обещание шире решения. Честно об этом не сказано.
- Отчёта «выплаты месяца против их снимков» и статуса документа на дату выплаты нет. Об этом молчат.
- Основание (причина) остаётся только у смены лейбла и деактивации. Р5 делает `document_id` необязательным.

**Замечание**
Р25: добавить в решение одну строку. Либо audit пишет «до» и «после» для записей решений, либо лента честно называется «кто и когда», а значения берутся из версий таблиц решений. Р11 и Р13: при смене id договора на id документа и удалении `track_labels` старые записи audit должны по-прежнему находить объект. Нужна таблица соответствия или проверка перед миграцией. Это условие этапа, не блокер.

**Что мне было непонятно**
Что значит «лента = audit + таблицы решений»: склейка на чтении по id или новая выборка. Как она показывает закрытую запись.
