# менеджер_паблишинга / оператор

1. **Кто я и что делаю каждый месяц.** Оператор: загружаю отчёты B17, связываю авторов из отчёта с людьми-получателями, песни с ISRC, веду условия паблишинга по типам операций и слежу, что деньги паблишинга не застряли в C.

2. **Пять моих сценариев.**
- **Загрузить квартал B17.** Файл, проверка, строки в базе. Работает: `POST /publishing-v2/files`, страница «Паблишинг v2» (`pages/reference/publishing-v2/PublishingV2Page.tsx`); замена и откат: `…/files/:id/remove`. Но старый модуль паблишинга живёт рядом (`pages/reference/publishing/PublishingPage.tsx`, `/publishing/b17`, `/publishing/statements/:id/replace`): какой из двух мой, из экрана не ясно.
- **Связать автора с человеком один раз.** Вкладка «Связи»: `GET/POST /publishing-v2/links`, есть рекомендация (`LinksTab.tsx`, поле `recommendation`), новое решение заменяет старое. Работает. В базе 34 автора, 33 связи. Старый путь `POST /publishing/writers/:norm/map` делает то же другим словом.
- **Привязать песню к ISRC.** `GET /publishing-v2/songs/:id/candidates`, `POST …/isrcs` (вкладка «Треки»). Работает технически, но из 1169 песен ISRC есть у одной. Руками не осилить.
- **Задать условия по типу операции (механика, исполнение, синхрон) с датой.** `POST /publishing-v2/terms`, отмена `…/terms/:id/cancel` (только последнее условие владельца). Работает; бумага-основание отдельно.
- **Узнать, почему деньги автора ждут.** Нужна очередь C по причине (`writer_unmapped`, `publishing_terms_unconfirmed`), `GET /queue/:reason` и сигналы. Частично: очередь есть, но от строки очереди до нужной вкладки паблишинга я иду сам. Прямого «исправь здесь» не нашёл.

3. **Три боли сегодня.**
- **Две системы паблишинга одновременно** (v1 `/publishing/*`, v2 `/publishing-v2/*`): одни и те же слова («автор», «писатель», «songwriter», «writer») значат разное, и я помню, где что делается.
- **Песни без ISRC.** Связь песни с каталогом по названию; кандидатов предлагают, но подтверждать приходится по одной песне. Связь «автор → человек» есть, «песня → релиз/трек» почти нет: так я не вижу, чей это трек в мастере.
- **Автор в отчёте пишется разными строками** (варианты написания, юр. имена). Список написаний виден на странице автора, но слияние или новое написание я проверяю глазами. Дубль с артистом мастера (тот же человек под ником) система не подсказывает.

4. **Что нельзя ломать.**
- Отчёт неизменен, мои решения лежат отдельно, и «Money is not touched» при связывании: я могу ошибиться и поправить без пересчёта чужих денег.
- Новое решение заменяет старое, строка остаётся с кем и когда.
- Откат файла с возвратом заменённых.
- Рекомендация «кого связать» на вкладке связей: не убирать.
- Отмена ошибочного условия с историей.

5. **Что я сочту усложнением.**
- Ещё одна страница «люди», куда нужно идти, чтобы связать автора, вместо вкладки «Связи».
- Отдельные шаги «создать человека», «потом связать», «потом подтвердить бумагой» подряд для одного автора.
- Новое слово вместо автор / песня / связь, которое я уже выучил.
- Требование выбирать лейбл или книгу там, где автор очевидно один.

6. **Чего не хватает продукту.** Единый реестр «кто есть кто» с подсказкой «этот автор, похоже, уже есть как артист или человек» при каждой связи, потому что сегодня я связываю автора по имени и строке, а не по найденному человеку; и очередь «песни без ISRC» с пакетным подтверждением, потому что 1168 из 1169 песен не привязаны.
