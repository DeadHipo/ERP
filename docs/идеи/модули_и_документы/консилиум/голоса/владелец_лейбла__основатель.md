# владелец_лейбла / основатель

1. **Кто я и что делаю каждый месяц.** Основатель: раз в месяц смотрю, сколько лейбл заработал и сколько должен людям, подписываю выплаты, а в перспективе показываю каталог и обязательства покупателю.

2. **Пять моих сценариев.**
   - **Минутный взгляд на лейбл.** Открыть обзор: получено (A), подтверждено чужим (B), ждёт (C), наше, и проверка «расхождение = 0». Работает: страница `pages/work/OverviewPage.tsx` + `OverviewKpis.tsx` (четыре карточки), `GET /overview`. Но «сколько я должен людям к выплате сегодня» на обзоре не вижу: B не равно «можно платить сейчас».
   - **Сколько должен людям.** Сумма к выплате по всем владельцам. Работает частично: `GET /owners/payables`, `GET /owners/payroll`, страница владельцев (`OwnersPage.tsx`, «Посчитать все»). Итога «долг лейбла» одной цифрой в обзоре нет; считается отдельным, тяжёлым запросом.
   - **Что застряло.** Очередь C по причинам и сигналы. Работает: `QueueStrip`, `SignalStrip` на обзоре, `GET /queue/:reason`, `GET /signals`. Не вижу, кто именно должен это разобрать и сколько это стоит в деньгах по сроку.
   - **Согласовать и подписать выплату.** Проверить допуск (договор, держатели, получатель) и нажать выплату. Работает: `payout-gate`, вкладка `AdmissionTab`, `GET /settlements/admission`; роль `org_admin`.
   - **Показать каталог покупателю: что принадлежит лейблу, на каких условиях, с какими обязательствами.** Не работает / не нашёл: есть `GET /tracks/catalog`, `/tracks/summary`, но нет страницы «каталог для оценки» с долей лейбла, сроком прав и невыплаченными долгами по трекам.

3. **Три боли сегодня.**
   - Обзор и деньги к выплате живут на разных экранах и считаются по-разному (период для чтения, `asOf` для платежа); приходится помнить, что B не равно «можно платить».
   - Чтобы понять «что застряло», нужно идти от причины C к строке, затем к человеку/документу, то есть к менеджеру; сам я не вижу, кто держит каждый вопрос.
   - Люди, псевдонимы, авторы паблишинга и договоры связаны по имени/строке и через операторские решения; уверенности «это один человек, ничего не потеряно» нет, пока кто-то не сверит руками.

4. **Что нельзя ломать.**
   - A = B + C + наше, и контрольная строка «расхождение» на обзоре.
   - Каждая сумма пересчитывается из сырых отчётов; выплата замораживает снимок.
   - «Ники не сальдируются»: платится сумма положительных позиций, а не чистая формула.
   - Допуск к выплате одной функцией (договор, держатель, получатель, порог).
   - Срез «Кабинет 15.10» как точка отсчёта, сверки сентября.
   - Роли: менеджер лейбла не видит деньги всей организации.

5. **Что я сочту усложнением.**
   - Ещё одна страница для того же вопроса «сколько и кому» (уже есть обзор, владельцы, выплаты, срезы, сверка).
   - Новое понятие рядом с A/B/C/наше: оно обязано объяснять деньги теми же словами.
   - Любой шаг «сначала свяжи, потом смотри» на моём пути: мне нужен ответ, а не подготовка данных.
   - Внутренние слова (книга, позиция, reach, срез) в моих карточках без подсказки.
   - Вторая цифра «заработано» с другим периодом без пометки, откуда она.

6. **Чего не хватает продукту.**
   - Строка «должны людям сегодня» на обзоре, из того же расчёта, что и кнопка выплаты, потому что это второй из трёх моих вопросов.
   - «Что застряло» с ответственным и возрастом, потому что без владельца вопроса очередь не двигается.
   - Единый реестр «кто есть кто» (человек, ники, автор, договор, реквизиты), потому что это основа и выплат, и оценки каталога.
   - Вид «каталог и обязательства» для сделки, потому что в продаже важно, чьё, на сколько и что должны.
   - Расчёты при этом не менять: любая новая цифра обзора должна читать существующий расчёт, а не считать заново.
