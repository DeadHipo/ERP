# оператор_данных / опытный

1. **Кто я и что делаю каждый месяц.** Грузу отчёты Believe (по аккаунтам и лейблам) и выписки B17, слежу, чтобы строки лейбла, новые ISRC (около 1 000 в месяц, 26 311 треков в каталоге) и авторы B17 не повисли в очереди C.

2. **Пять моих сценариев.**
   - **Загрузить отчёт Believe.** Файл, аккаунт, лейбл-книга, проверка, `loaded`. Работает: `POST /sources/believe` (`operations.ts`, ~964), страница `reference/sources/SourcesPage.tsx`, 48 файлов `loaded`. Эталон считается заново, строки в ClickHouse.
   - **Новая строка лейбла в отчёте.** Увидеть непривязанную строку и сопоставить с лейблом. Работает частично: причина `label_unmapped` в очереди C (`i18n/ru/reasons.ts:10`), диалог `LabelAliasDialog` (`work/actions/dialogs`), онбординг показывает «Строки без алиаса» (`i18n/ru/onboarding.ts:17`). Алиас живёт без периода, поэтому смену строки ISRC во времени он не выражает.
   - **Новые ISRC без сплита.** Список «кто ждёт сплита» и закрытие его импортом. Работает: `no_split` в `/queue/:reason`, импорт `POST /splits/import` (D-172), `RegisterTrackDialog`. Одного списка «новое за месяц» нет.
   - **Выписка B17: загрузить, связать авторов, заменить.** Работает: `PublishingV2Page`, `LinksTab`, `ReplaceStatementDialog`, причина `writer_unmapped`, рекомендации по имени. Живёт в двух сторонах: v1 и v2 остаются рядом в меню `reference/`.
   - **Сверить месяц: «всё ли разобрано».** Не нашёл единого экрана. Есть Обзор (A = B + C + наше), Очередь ожидания по причинам, Сигналы (`work/signals`), Онбординг-чеклисты (`GET /onboarding`). Четыре места, у каждого свой счётчик.

3. **Три боли сегодня.**
   - **Решения разбросаны по разным экранам.** Алиас лейбла, сплит, связь автор→владелец, песня→ISRC, дубль артиста (`/artists/duplicates`): шесть видов ручной работы, шесть диалогов, нет итога «в этом месяце к тебе пришло N решений». Считаю сам.
   - **Лейбл связан по строке.** `label_name` из отчёта → `label_aliases` без периода. Опечатка или новый регистр в Believe, и «наше» тихо уходит в C. Приходится помнить, какие 34 строки уже заведены.
   - **Две истории лейбла ISRC.** `track_labels` (каталог) и то, что видят деньги, расходятся на 4 134 ISRC. Я не знаю, какой из них править, когда трек переехал.

4. **Что нельзя ломать.** Загрузка без слияния равных ключей, `loaded`-реестр: невыгруженный файл не считается. Пересчёт из сырых строк, а не накопление. Очередь C с причиной и подсказкой действия (`i18n/ru/work.ts:98-102`). Замена выписки B17 с `superseded` вместо удаления. Рекомендует система, ставит человек. Откат загрузки без потери следа.

5. **Что я сочту усложнением.**
   - Отдельный шаг «утвердить загрузку» перед очередью, раз уже есть dry-run.
   - Ещё один экран «входящие» поверх Очереди, Сигналов и Онбординга, вместо слияния их.
   - Новое понятие «источник/провайдер/адаптер» в интерфейсе: мне хватает слов «аккаунт», «лейбл», «отчёт».
   - Привязка авторов B17 через общий «реестр людей» с обязательным подтверждением для каждого, если имя совпало точно.
   - Разные формы для Believe и B17 для одного и того же «загрузить файл».

6. **Чего не хватает продукту.** Один список «ручные решения месяца» (кто/что ждёт, по типам, со счётчиком и сроком), потому что ответ на мой главный вопрос сегодня надо собирать из четырёх страниц; и подсказка при загрузке «в этом файле N новых ISRC, M новых строк лейбла, K новых авторов» ещё до расчёта.
