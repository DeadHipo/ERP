# поддержка_артистов / первая_линия

1. **Кто я и что делаю каждый месяц.** Первая линия поддержки: отвечаю артистам и их менеджерам на типовое «где мои деньги / почему такая сумма / когда выплата», разработчика не зову; терминов «слой», «книга», «охват» не знаю.

2. **Пять моих сценариев.**
   - **«Сколько мне сейчас можно получить?»** Ищу артиста (`GET /search`), открываю страницу артиста (`pages/artists/ArtistBalanceTab.tsx`, `GET /artists/:id/balance`) и читаю «заработано / ждёт / возмещено / выплачено». Работает частично: сумма «к выплате» и кнопка лежат у владельца (в самой вкладке подсказка «выплата и остаток — у владельца»), надо перейти на вторую страницу (`pages/owners/BalanceTab.tsx`, `GET /owners/:id/balance`). Если у владельца несколько ников, надо сложить в уме (деньги по никам не сальдируются, D-181).
   - **«Почему мало / ничего не пришло?»** Нужна одна фраза-причина. Есть: блок «ждёт по причинам» (`reasons.ts`, десять причин C) и допуск (`pages/owners/AdmissionTab.tsx`, `GET /settlements/admission`: холд, нет получателя, порог, «нужен ответ»). Работает, но причины разбросаны по двум вкладкам и говорят языком системы («owner_unconfirmed»-подобные формулировки), а не языком артиста.
   - **«Откуда эта сумма по моему треку?»** `GET /tracks/:isrc/explain` и вкладка «Деньги» трека (`pages/catalog/track/MoneyTab.tsx`). Работает, но это экран для оператора: «состояние после каждого слоя». Готового текста для артиста нет.
   - **«Пришлите выписку за месяц».** Не нашёл. Есть payroll csv для лейбла (`GET /owners/payroll`) и снимок выплаты (`GET /settlements/operations/:id/snapshot`), но выписки артисту «по месяцам, по платформам, с удержаниями» как документа нет; собираю скриншотами.
   - **«Я отправил запрос на выплату / оспариваю сумму».** Холд с типом «запрос артиста» или «оспаривание» заводится (`POST` в допуске, `AdmissionTab`); работает. Но ответа артисту из системы нет, и статуса «мой запрос в работе» я не вижу списком по артистам.

3. **Три боли сегодня.**
   - Ответ по одному человеку собирается из трёх мест: артист (ник) → владелец (юрлицо/получатель) → лейбл/книга. Артист пишет «я», а в системе «я» — несколько никнеймов и несколько книг; я сверяю руками, чей это ник и в каком лейбле.
   - Расчёт по человеку считается секунды (в MCP-подсказке: список ~10 с, одного владельца ~7 с). В звонке с артистом это ожидание и риск, что цифры «ушли» к моменту следующего вопроса; нет понятия «на какой месяц отчёта я смотрю» в одной строке сверху.
   - Причина «ждёт» не ведёт к действию. Вижу «нет документа», но кому написать (юристу, менеджеру лейбла, оператору) и что уже запрошено, не вижу. Иду в чат и спрашиваю человека.

4. **Что нельзя ломать.** Цифры из одного расчёта и «ничего не хранится как начисление» (я могу доверять числу). Разложение «ждёт по причинам» с итогом. Пояснение по ISRC (`explain`). Допуск с понятной причиной отказа (`payout-gate`). Холды как запись «артист просил / спор». Поиск по нику, алиасу, треку (`/search`).

5. **Что я сочту усложнением.** Третью сущность между артистом и владельцем в интерфейсе; ещё один экран «кто есть кто», на который надо ходить перед ответом; английские коды причин в тексте для артиста; обязательный выбор лейбла/среза/`asOf` до того, как я вообще увижу сумму; разнесение «заработано» и «к выплате» по разным страницам.

6. **Чего не хватает продукту.** «Карточки ответа артисту»: одна страница по человеку (все его ники и книги вместе), где сверху «можно получить / ждёт / удержано / почему / следующий шаг и кто отвечает», с кнопкой «скопировать ответ» простым русским и историей обращений; причина «ждёт» должна называть исполнителя действия.

Расчёт не меняется: всё перечисленное это чтение и подсказки поверх существующих чисел.
