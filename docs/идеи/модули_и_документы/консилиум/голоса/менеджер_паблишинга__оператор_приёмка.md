# менеджер_паблишинга / оператор: приёмка

**Вердикт:** принимаю с замечанием

**Что из моего первого голоса закрыто**
- Две системы паблишинга: Р8, Р9 убирают v1, в меню остаётся один «Паблишинг», слово «v2» уходит.
- «Кто есть кто» и дубль с артистом мастера: Р19 (автор виден на карточке владельца), Р20 (подсказка дубля по ходу ввода, решает человек).
- Моё «нельзя ломать» не тронуто: вкладка «Связи» и рекомендация остаются (С2), новое решение заменяет старое, «закрытые зоны 0», новой страницы «люди» нет.

**Что не закрыто или отложено**
- Очередь «песни без ISRC» с пакетным подтверждением (1168 из 1169): итог молчит. Пакетные действия есть только в Р23, а она вынесена в отдельную цель без срока. Честно сказано про Р23, но про песни прямо не сказано ничего.
- Р10 удаляет алиасы авторов pubv2: второе написание автора станет новым автором и потребует нового решения. Сценарии сами пишут, что риск «не оценён и не закрыт».
- Р18 убирает `old_map`, один из четырёх источников рекомендации «автор → владелец»; качество подсказок «не измерено».

**Замечание**
Не блокер: деньги и мои решения не ломаются. Но Р10 и Р18 бьют по моей главной задаче, связать автора один раз и навсегда. Перед этапом 1 нужен замер на живых 34 авторах: сколько написаний держат алиасы и сколько рекомендаций даёт `old_map`. Если алиасы несут реальные варианты написания, колонка `name_norm` должна принять их, а не потерять. Очередь песен без ISRC записать отдельной целью, а не молчать о ней.

«Закрытые зоны», «проекция», «срез», «книга», «этап Э» без расшифровки. Из Р19 не ясно, можно ли связать автора прямо с карточки владельца или карточка только показывает связь.
