# менеджер_лейбла / руководитель: приёмка

**Вердикт:** принимаю с замечанием

**Что из моего первого голоса закрыто**
- Р20 и Р19: подсказка дубля по ходу ввода, в том числе в сплите и в предпросмотре импорта (ник в сплите того же ISRC или UPC, имя автора B17, слова в другом порядке); автор паблишинга на карточке владельца. Это мой главный вопрос, и решает человек, без автослияния. 409 больше не показывает чужих артистов: изоляцию по лейблам не ломают.
- Р11: договор одним шагом, без «создай там, свяжи здесь». Нового реестра «кто есть кто» нет (Р19, отклонение реестра сторон): четвёртого места поиска не будет.
- Р5, Р25 и «числа не меняются»: операторский след и предпросмотр «всё или ничего» остаются.

**Что не закрыто или отложено**
- Рабочий список «что мне доделать» (75 ников без сплита, 849 без владельца): это Р23, вынесено в отдельную цель вне упрощения. Сказано честно, но до неё живу на сегодняшних страницах.
- Релиз до выхода отчёта: боль 9 не разобрана ни одним решением. В итоге об этом молчат, упомянуто только в замечаниях оформителя (п. 5). Это нужно сказать прямо.
- Совместные импринты (В1): исправить сам не смогу, только через оператора. Честно названо.

**Замечание**
- Р20: не названо, как менеджер без звонка оператору разрешает пограничный случай («тот же человек под другим ником»), если совпадение только по автору B17. Нужно, чтобы подсказка показывала, почему совпало.
- Р21/С11: отказ при двух получателях не говорит, где человек выбирает, какого оставить.
- Свой ник менеджера без сплита ему не виден (замечание оформителя 4): включить в Р20.

**Что мне было непонятно**
«Закрытые зоны», «срез», «ПК1…ПК4», «книга», «проекция»: для менеджера это внутренний язык. Итог нужно читать вместе со сценариями.
