# второй_лейбл / крупный

1. **Кто я и что делаю каждый месяц.** Дистрибьютор с десятками саблейблов, пришёл в чужую ERP как вторая организация: каждый месяц загружаю отчёты Believe по нескольким аккаунтам, свожу долю каждого саблейбла и плачу сотням артистов.

2. **Пять моих сценариев.**
   1. *Подключить компанию.* Хочу сам зарегистрироваться, получить организацию и админа. Сегодня нет самообслуживания: организацию создаёт только системный администратор (`POST /orgs`, `ability: system`, `operations.ts:134`; страницы `pages/system/OrgsPage.tsx`, `OrgPage.tsx`), пользователей заводит он же. Есть скрипт `create-user.ts`. Не работает без вашего человека.
   2. *Завести десятки лейблов и саблейблов с аккаунтами Believe и строками импринтов.* Есть: `/labels`, `/labels/:id/accounts`, `/aliases`, `/rules` (`operations.ts:849-919`), чек-лист организации `GET /onboarding/organization` (`pages/work/onboarding/OrgChecklist.tsx`). Но по одному лейблу за раз, пакетной загрузки лейблов и правил саблейблов не нашёл.
   3. *Залить каталог и сплиты пачкой.* Есть: `POST /splits/import` (до 5000 строк, предпросмотр dryRun, всё или ничего, `operations.ts:769`), импорт реестра релизов, импорт операций (`:1211`). Для сотен тысяч ISRC лимит 5000 строк и 10 МБ означает десятки загрузок. Артисты и владельцы создаются самим импортом сплитов: это работает.
   4. *Загрузить договоры.* Документы и договоры заводятся по одному (`POST /documents`, `/contracts`, `operations.ts:669-724`). Массовой загрузки договоров и провайдера (PandaDoc, индекс) для моей организации не нашёл. Не работает в масштабе.
   5. *Раздать доступ менеджерам по лейблам.* Есть: роль `label_manager` с привязкой к своим лейблам, 404 на чужое, без денег всей организации (`pages/users/UsersPage.tsx`, `abilities.ts`). Работает.

3. **Три боли сегодня.**
   - Первый шаг всегда через вас: организацию и первого админа создаёт системный админ; без вашего человека я не стартую.
   - Лейбл «наш» держится на строке: `label_name` из Believe связывается с лейблом через алиас-строку. У нас десятки саблейблов, новая строка в отчёте = «наше» ждёт (`label_unmapped`), и я узнаю об этом после загрузки, а не до.
   - Онбординг — чек-лист, а не мастер: он показывает, что не сделано (ISRC без сплита, псевдонимы без владельца, строки без документа), но порядок и связывание я делаю сам по десяткам списков. Автор паблишинга и артист связываются руками.

4. **Что нельзя ломать.**
   - Изоляция организации: данные чужой организации я не вижу ни при каких ошибках (D-170, `org_id` везде, тест `org-scope.test.ts`).
   - Чужое не считается моим: роль менеджера лейбла видит только свои лейблы.
   - Деньги пересчитываются из сырья, а не хранятся; выплата замораживает снимок; предпросмотр импорта до записи; всё или ничего.
   - Поддержка заходит только по моему разрешению на срок до 7 дней (`support_grants`): для крупного клиента это условие доверия.
   - Журнал операторов (`X-Operator`, audit).

5. **Что я сочту усложнением.**
   - Отдельный шаг или страница для каждой «пары» (автор→владелец, песня→ISRC, псевдоним→документ) без пакетного режима.
   - Понятия, которые приходится учить до первой загрузки: книга, перимeтр, охват, срез, C-причины. Мне нужно «чей трек, сколько, почему ждёт».
   - Если для подключения нового саблейбла надо трогать пять экранов (лейбл, аккаунт, алиас, правило, пользователь) вместо одной формы.
   - Обязательный документ до того, как я вообще увижу деньги в обзоре.

6. **Чего не хватает продукту.**
   - Самостоятельный онбординг организации: мастер «лейбл, аккаунт, первый отчёт, предупреждение о неизвестных строках, сплиты, пользователи» с порядком шагов, а не только список остатков.
   - Пакетное заведение лейблов, саблейблов и их правил из таблицы, с предпросмотром, как в импорте сплитов: у меня десятки, не единицы.
   - Единый реестр «кто есть кто» с подсказкой о дублях при заведении артиста: при импорте сотен сплитов дубли псевдонимов неизбежны.
   - Приём договоров как документов из любого источника (загрузка пачки, провайдер) с привязкой к владельцу, иначе юридическое основание для каждой выплаты я собираю вручную.
