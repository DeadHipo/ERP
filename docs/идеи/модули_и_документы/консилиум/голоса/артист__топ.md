# артист / топ

1. **Кто я и что делаю каждый месяц.** Артист с несколькими никами, мастер и паблишинг, плюс реклама моих релизов: раз в месяц хочу понять, сколько мне причитается, что удержали и когда платят.

2. **Пять моих сценариев.**
   - **Сколько мне должны сегодня по всем никам.** Один итог и разбивка по никам. Работает частично: у оператора есть `GET /owners/:id/balance` и `/artists/:id/balance` (`operations.ts`), страницы `pages/owners/BalanceTab.tsx` и `pages/artists/ArtistBalanceTab.tsx`. Для меня самого экрана нет: ролей в `auth/abilities.ts` шесть (org_admin, label_manager, system, support, local, reader), «артиста» среди них нет. Я вижу только то, что мне перешлют.
   - **Откуда деньги по треку.** `GET /tracks/:isrc/money`, `/explain`, `/breakdown/:month` существуют и считаются хорошо. Но это экраны оператора, в моём кабинете их нет.
   - **Почему часть денег «ждёт».** Работает: `ArtistBalanceTab` показывает ожидание по причинам (`waitingBreakdown`, подписи в `shared/reasons.ts`). Причины («нет документа», «лейбл не сопоставлен») написаны языком системы, не моим.
   - **Что удержано: аванс и реклама.** Аванс гасится только из дохода того же ника (рекуп), реклама снимается из выплаты сразу (D-157). Данные есть (`/ads`, `/ads/summary`, позиции аванса в балансе). Одним понятным списком «удержано за месяц, за что» я его не нашёл.
   - **Когда придёт выплата.** Есть допуск (`/settlements/admission`: получатель, холды, ответ «платить», порог договора, по умолчанию $50) и `payout.reason` в балансе. Дату я не получаю: решение принимает казначей на странице допуска. Причины отказа техничны («owner_not_confirmed», «needs_answer»). Мне ни одна не переведена на «что сделать мне».

3. **Три боли сегодня.**
   - Нет выписки, понятной мне: payroll (`/owners/payroll`, json/csv) устроен для лейбла, не для артиста. Мне пересказывают цифры вручную.
   - Ники не сальдируются (D-181): «должен» по одному нику не гасится «положительным» другим. Выплата идёт по сумме положительных позиций, а не по общему итогу. Я не вижу объяснения, почему мой итог в одном месте и сумма к выплате в другом разные (`payable` против `payableShown`).
   - Мастер и паблишинг считаются разными путями: B17 связан с человеком отдельным решением оператора (`links.songwriter_owner`), и пока связи нет, мои деньги паблишинга не видны в моём балансе. Узнаю об этом только от человека.

4. **Что нельзя ломать.**
   - Деньги считаются заново из строк отчёта и сходятся: A = B + C + наше. По цифрам верю системе.
   - Объяснение по треку и месяцу (`explain`).
   - Аванс гасится только с дохода своего ника; позиции по никам раздельны.
   - Снимок выплаты хранится и неизменен.
   - Холд и запрос на ответ «платить» перед первой выплатой.

5. **Что я сочту усложнением.**
   - Любая связь «человек - ник - автор - договор», которую надо вести мне самому в нескольких местах.
   - Ещё одна страница или отчёт со своими цифрами, расходящимися с балансом: у меня должна быть одна сумма.
   - Новые слова вместо «заработано / удержано / ждёт / к выплате», например книга, срез, охват, позиция.
   - Отдельный вход для паблишинга и отдельный для мастера.

6. **Чего не хватает продукту.** Артистского вида «моя выписка за месяц» (заработано по мастеру и паблишингу, удержано с причиной, ждёт и что нужно для разблокировки, к выплате и когда) — потому что система уже знает все эти числа, но отдаёт их только оператору и на его языке.
