# Демо графа расчёта: `index.html`

Дата: 2026-11-04. Автономная страница, без сборки и внешних зависимостей (vanilla JS, inline SVG, CSS).
Данные — `cases.js` рядом (`window.CASES`, схема в `СХЕМА.md`). Если `cases.js` нет или он пуст, страница берёт
встроенный `window.CASES_FALLBACK` и пишет об этом вверху («показаны запасные кейсы»).

## Как открыть

Двойной клик по `index.html` (file://). Кейс можно открыть по хэшу: `index.html#G18b`. В консоли браузера при загрузке
печатается результат самотеста (`самотест демо: всё сходится`); повторно — `window.__demo.selfTest()`.

## Что где

- **Слева** — список кейсов из `CASES`: id, название, уровень (простой / средний / сложный), источник. Выбор меняет всё.
- **Шапка кейса** — название, описание, источник; у каждого юнита — ключ `upc|salesMonth|labelName|account`, ISRC,
  месяцы, строка лейбла, net, схема (`master/standard`), статус, если не `allocated`; у отрицательного юнита — пояснение
  «возврат, это не "забрали у артиста"».
- **Переключатель «по юнитам / сумма по трек-месяцу»** — только если юнитов больше одного (G24). Сумма складывает
  рёбра с одинаковыми `from, to, kind, ruleId` (BigInt по пико, 12 знаков), узлы — по id; у ребра видно «юнитов: N».
  Трейс в режиме суммы не складывается.
- **Вкладки:**
  1. «Таблица-дерево» (по умолчанию) — раскрываемое дерево от `net`: узел → его рёбра (сумма в центах, вид, правило,
     процент, база, документ, категория/статус, допущение) → подузлы. Узел с двумя входами (`pool`) раскрыт один раз,
     дальше «раскрыт выше». Под деревом таблица стоков `layers-table` со строкой «Всего» = net.
  2. «Граф» — SVG: колонки 0…4 слева направо (пул ставится в полуколонку и сливается с колонкой доли лейбла, если
     между ними нет рёбер), кривые Безье, толщина ∝ |amount| (минимум 1,5 px), подпись в центах, 12 знаков в `title`.
     Цвет: B зелёный, C красный, наша доля серо-синий, промежуточные серые; допущение — пунктир; недостача — ⚠ у узла
     и подпись «не хватило N по правилу R». Узел: `in = out` (или обе суммы), сток: «начислено» / «начислено, ждёт».
     Подписи сумм раздвигаются, чтобы не наезжать друг на друга.
  3. «Входы узлов» — инспектор: вид правила, id, смысл, поля как в базе, узел, который его читает; ниже трейс по слоям
     свёрнутыми блоками.
- **Детали** — клик по ребру (граф или дерево) или узлу открывает плавающую панель `flow-edge-detail`: откуда, куда,
  сумма (центы и 12 знаков), вид, правило, документ, процент, база, категория, причина, допущение и формула
  (`50 % × 30,60 = 15,30` или `остаток = вход − Σ правил = 36,00 − (5,40 + 15,30) = 15,30`).
- **Внизу** — легенда, сноска про центы, проверки: из расчёта (`checks` кейса: баланс узлов, стоки = net, рёбра =
  аллокации, знак) и пересчёт на странице (баланс узлов, Σ стоков = net, знак) — зелёные/красные, с перечнем проблем.

## Хуки для e2e (из `консилиум/qa.md`)

Рисуется только активная вкладка, поэтому хуки не дублируются.
`trackflow` (`data-isrc`, `data-month`, `data-unit-key`, `data-units`) — по одному на юнит или один на сумму;
`flow-node-<id>` (`data-in`, `data-out`, `data-balanced`) в графе и в заголовках узлов дерева;
`flow-edge` (`data-from`, `data-to`, `data-kind`, `data-amount` — сырая decimal-строка, `data-category`,
`data-assumption`, `data-rule-id`) в графе и в строках дерева; `flow-edge-label` — отформатированная сумма;
`flow-edge-detail` — панель; `layers-table` и `layers-total` (`data-amount`); `flow-empty` — нет юнитов или рёбер.

## Какие решения консилиума отражены

- **Р5** — ключ юнита у каждого контейнера; сумма по трек-месяцу складывает одинаковые `from→to#kind#ruleId`
  и показывает число юнитов; раскрытие — по юниту.
- **Р6** — нулевые рёбра и рёбра-остатки рисуются (толщина 1,5 px, подпись `0,00`), узел виден закрытым.
- **Р9** — недостача — подпись узла (⚠ + текст), не ребро; баланс проверяется только на внутренних узлах.
- **Р12** — таблица-дерево — первая вкладка и вкладка по умолчанию; печатается (при печати скрыты список и панель).
- **Р17** — центы в таблице, 12 знаков по наведению и в панели; одна ось цвета B / C / наша доля, причина текстом;
  «начислено, ждёт» вместо «дошло»; `label_unmapped` подписан «ждёт наша доля, не артист»; у остатков
  «остаток = вход − Σ правил»; пометка «Расчёт на сегодня, не выписка».
- **Продакт, «Риски понимания»** — строка сплита показана контейнером «строка A → пул / A»; сноска про расхождение
  центов на 0,01; легенда обязательна; пояснение к отрицательным юнитам.

## Запасные кейсы

`G01` (одна строка A 50 %), `EX100` (пример README §5 на 100,00), `EXSF` (недостача пула, README §5),
`G24mini` (два юнита: net 100 и 50, сплит A 50 %). Суммы посчитаны вручную; самотест проверяет баланс узлов,
Σ стоков = net, знак, рёбра в `artist:X` = аллокации последнего слоя трейса, агрегацию (A 75 из 2 юнитов, net 150)
и форматирование (`−1 234,57`).

## Что намеренно не сделано

- Нет ссылок на карточки документов и правил (демо без API); документ показан id.
- Нет карточки владельца (`owner-flow`, Р14) и выборки `/allocations` (Р16): это другие задачи.
- Раскладка графа простая: колонки + барицентр + раздвижка подписей. Длинные рёбра (net → ремиксер, строка → артист)
  могут проходить под узлами промежуточных колонок; без фиктивных узлов это не исправить.
- Цвета не проверены на дальтонизм отдельно; категория всегда продублирована текстом.
- Нет тёмной темы и мобильной раскладки (граф прокручивается по горизонтали).
- Число в `Number()` используется только для толщины линии; все суммы — BigInt по пико и строки.
