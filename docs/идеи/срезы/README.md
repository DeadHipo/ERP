# Срезы — коротко

**Срез** — это «как было на момент» в книге одного лейбла. Всё, что до среза, — внутри; всё, что после, — нет.

## Что у среза есть

- **Название** — «До ERP», «2026».
- **Дата** — например 15.10.2026.
- **Границы по источникам** — даты, всегда первое число месяца, «до этой даты внутри»; подставляются сами,
  можно поправить:
  - Believe: по умолчанию 01.10.2026 (сентябрь внутри); если кабинет видел только август — 01.09.2026;
  - публишинг: 01.10.2026 → Q3 внутри, Q4 после;
  - реклама: как Believe;
  - операции: с датой до даты среза.

## Что я с ним делаю

1. Создаю срез — вижу по каждому нику **сальдо на момент среза**: недоплатили 120 $, аванс не погашен на 300 $.
2. Свожу в ноль, **привязывая операции к срезу** (дата у операции может быть любой, хоть ноябрь):
   - недоплата → выплата «на срез»;
   - расхождение → корректировка «на срез»;
   - долг, который гасим позже → **перенос**: на срезе 0, после среза −300, гасится будущим доходом.
3. Сигнал «незакрытые на срезе» показывает, у кого ещё не ноль. Пришёл поздний отчёт за август — человек снова
   появится в сигнале.

## Чего срез не делает

- Не меняет расчёт и общую сумму к выплате — только показывает и привязывает.
- Не блокирует выплаты, не «закрывается», у него нет статусов.
- Нынешний старт 15.10 не трогает: он работает как раньше.
- Срезы только у лейблов (не у организации), управляет ими администратор организации.

## Что появится

- В базе: таблица срезов и у операции поле «отнесена к срезу».
- В интерфейсе: страница «Срезы», страница среза с таблицей сальдо, поле «Отнести к срезу» в диалогах выплаты и
  операции, сигнал «незакрытые на срезе».
- **У владельца** — вкладка «Срезы»: по разделу на каждый срез — сальдо по его никам на срезе, операции,
  отнесённые к этому срезу, и сколько заработано / выплачено между прошлым срезом и этим; последний раздел —
  «после последнего среза». В списке операций — колонка «Срез».
