# План разработки: саблейблы и условия по трекам

2026-11-17. Решение владельца в этот день: **две простые таблицы по образцу паблишинга v2** — справочник саблейблов
(только название) и условия саблейбла по ISRC в модуле `links` (процент, срок, документ), как `links.publishing_terms`.
Этот план заменяет схему из `проект_привязок.md`. Его аудиты (`аудит/`) остаются в силе там, где речь о расчёте,
порядке перехода и суммах.

## Что входит и что нет

**Входит:** справочник саблейблов; условия «саблейбл → ISRC» с процентом и сроком; пробный прогон и запись пачкой;
закрытие, отмена, документ задним числом; отчёт саблейбла «трек × месяц» (только чтение); подсказки новых треков;
страницы по образцу паблишинга v2; первичное заполнение трёх саблейблов из приложений договоров.

**Не входит (отдельные цели потом):**
- кто получает деньги саблейбла и переключение расчёта на условия (сейчас деньги идут по старым правилам);
- права доступа в целом: на этом этапе классы действий берутся как у паблишинга v2, пересмотр — отдельно;
- реклама, аванс, получатель выплаты, канал, порог, ведомость;
- ссылка и вход для самого саблейбла;
- удаление `label_rules` и `label_aliases`.

**Деньги не меняются ни на одном шаге этого плана.** Расчёт (`calculation.ts`, `layers/*`, `owner-scope.ts`,
`balance.ts`) условия не читает; тест границ это закрепляет.

## Модель в двух таблицах

**`labels.sublabels`** — справочник: `org_id`, `id`, `name`, `created_at`. Название уникально в организации (без
учёта регистра). Первичное заполнение — 15 сегодняшних саблейблов из `labels.labels` вида `sublabel` с теми же id, чтобы
отчёт мог сравнить условия с сегодняшними правилами.

**`links.sublabel_terms`** — условие саблейбла по треку, по образцу `links.publishing_terms` (D-185, D-188, D-192):

| колонка | тип | смысл |
|---|---|---|
| `org_id` | text | организация |
| `id` | text | |
| `sublabel_id` | text | саблейбл (без внешнего ключа: другой модуль, D-121) |
| `isrc` | text, CHECK формата | трек; обязателен |
| `percent` | numeric(9,6), 0 < p ≤ 100 | доля саблейбла от доли лейбла после артистов и участий |
| `valid_from` | date, первое число месяца | с какого месяца |
| `valid_to` | date или NULL, первое число, > `valid_from` | до какого (исключительно) |
| `document_id` | text или NULL | основание; NULL — деньги ждут |
| `note` | text или NULL | |
| `decided_by`, `decided_at` | | кто и когда решил |
| `document_by`, `document_at` | | кто и когда приложил документ позже |
| `cancelled_at`, `cancelled_by`, `cancel_reason` | | отмена |

Индексы: `(org_id)`; уникальный `(org_id, isrc, valid_from) WHERE cancelled_at IS NULL`; `(org_id, sublabel_id)`.

**Правила записи — те же, что у условий паблишинга:**
1. на ISRC в каждом месяце действует одна неотменённая запись;
2. новая запись с месяца X закрывает открытую запись трека этим месяцем (её `valid_to = X`); начало раньше или равно
   началу открытой — отказ `409 term_overlap`;
3. закрыть можно открытую запись, поставив конец;
4. отменить можно только последнюю запись трека; закрытая ею запись снова открывается (`valid_to` возвращается в
   прежнее значение);
5. приложить документ можно к записи без документа (один раз); больше ничего не правится.

Таблиц в базе: 48 → 50 (пока старые правила живут рядом); после переключения расчёта — 48.

## Бэкенд

### Б1. Миграция и схемы

1. `packages/backend/migrations/postgres/0033_sublabels.sql` (идемпотентно): `labels.sublabels`, `links.sublabel_terms`,
   индексы и CHECK; заполнение `labels.sublabels` из `labels.labels WHERE kind = 'sublabel'`.
2. Drizzle: `modules/labels/schema.ts` (`sublabels`), `modules/links/schema.ts` (`sublabelTerms`), с `orgId`.
3. `tests/org-scope.test.ts`: число таблиц организации 42 → 44, обе таблицы через помощник организации.
4. `tests/postgres.test.ts`: миграция применяется дважды.

### Б2. Модуль `labels`: справочник

`modules/labels/{repository,service,index}.ts`:
- `listSublabels()`, `sublabel(id)`;
- `createSublabel({ name })` → `409 sublabel_name_taken`;
- `renameSublabel(id, name)` → то же.

### Б3. Модуль `links`: условия

`modules/links/{repository,service}.ts`, по образцу `publishing_terms`:
- чтение: `sublabelTerms({ sublabelId?, isrc?, isrcs?, month?, withCancelled? })`, `sublabelTerm(id)`;
- `addSublabelTerms(rows, by)` — в одной транзакции для каждого трека: закрыть открытую запись, вставить новую;
  проверка правила 2;
- `closeSublabelTerm(id, validTo, by)`;
- `cancelSublabelTerm(id, by, reason)` — только последняя по треку, вернуть `valid_to` закрытой ею записи;
- `attachSublabelTermDocument(ids, documentId, by)` — только где документа нет.

Модуль ничего не знает о каталоге и документах: это проверяет фасад. `modules/links/CLAUDE.md` дополняется абзацем.

### Б4. Фасад: действия

Новый файл `facade/sublabels.ts`:
- `listSublabels()` — название, число открытых условий сейчас, число без документа;
- `createSublabel`, `renameSublabel`;
- `listSublabelTerms(filters)` — с названием трека из каталога и статусом документа;
- `addSublabelTerms(sublabelId, body, { dryRun })`. Тело: `{ documentId?, percent, validFrom, note?, items: [{ isrc,
  percent?, validFrom?, validTo? }] }`, до 5 000 строк. Пробный прогон — в `db.snapshot()`, запись — в одном
  `db.transaction()`, всё или ничего. Классы строк:

  | класс | вид | смысл |
  |---|---|---|
  | `new` | сведение | у трека не было условия |
  | `closes` | сведение | закроет открытое условие (саблейбл, процент, с какого месяца) |
  | `unchanged` | сведение | такое же условие уже открыто: запись пропускается |
  | `not_in_catalog` | предупреждение | ISRC нет в каталоге: условие заводится впрок |
  | `no_document` | предупреждение | деньги будут ждать |
  | `isrc_invalid`, `percent_invalid`, `date_invalid`, `empty_period`, `duplicate_in_request` | ошибка | |
  | `term_overlap` | ошибка | начало раньше или равно началу открытого условия трека |
  | `document_not_found`, `document_kind` | ошибка | документ не найден или не из видов документов сплита |
  | `sublabel_not_found` | ошибка | |

- `closeSublabelTerm`, `cancelSublabelTerm`, `attachSublabelTermDocument` — с теми же проверками.

### Б5. Фасад: отчёт саблейбла

Новый файл `facade/sublabel-report.ts`, **только чтение**, расчёт не меняется:
1. ISRC открытых и закрытых условий саблейбла;
2. один `calculate()` по этим ISRC через `scoped(modules, { isrcs, publishingLines: false })` (как деньги трека);
3. для каждого юнита: условие, действующее в его отчётный месяц; база = остаток доли лейбла юнита плюс сегодняшняя
   выплата саблейблу на этом юните (то есть доля лейбла до вырезки саблейбла — без нового умножения); часть саблейбла =
   `pct(база, процент)` (тот же помощник точности `layers/exact.ts`, 12 знаков);
4. статус строки: документ утверждён — «подтверждено»; документа нет, не утверждён или допущение — «ждёт» с причиной;
   у юнита без сплита — «ждёт: нет сплита», часть 0;
5. группировка (ISRC, отчётный месяц) с названием трека; итоги по месяцам и за период; формат json или csv.

Отчёт не показывает валовой доход трека, доли артистов и нашу часть (`модель_лейблов.md` §4). Тест: для саблейбла,
у которого условие совпадает с сегодняшним правилом, часть по отчёту равна сегодняшней выплате ему до знака.

### Б6. Фасад: подсказки

В `facade/sublabels.ts`: `sublabelSuggestions(month)` — ISRC юнитов месяца, у которых строка Believe ведёт через
алиас на лейбл с тем же id, что у саблейбла, а открытого условия на этот месяц нет; сумма net по треку; группировка по
саблейблам. Одно чтение ClickHouse по файлам месяца. Это подсказка: расчёт её не читает.

### Б7. API

Файл `api/routes/sublabels.ts`, подключение в `routes/index.ts`; запросы — `packages/shared/src/api-schemas.ts`,
ответы — `api-responses.ts`; каждая операция — в `api/operations.ts`.

| маршрут | что | класс (временно, как у паблишинга v2) |
|---|---|---|
| `GET /sublabels` | список | read |
| `POST /sublabels` | завести `{ name }` | admin |
| `PATCH /sublabels/:id` | переименовать `{ name }` | admin |
| `GET /sublabels/terms?sublabel=&isrc=&month=&noDocument=` | условия | read |
| `POST /sublabels/:id/terms?dryRun=1\|0` | добавить пачку | approve |
| `POST /sublabels/terms/:id/close` | `{ validTo }` | approve |
| `POST /sublabels/terms/:id/cancel` | `{ reason }` | approve |
| `POST /sublabels/terms/document` | `{ ids, documentId }` | approve |
| `GET /sublabels/:id/report?from=&to=&format=json\|csv` | отчёт трек × месяц | read_money |
| `GET /sublabels/suggestions?month=` | подсказки | read_money |

Обязательно вместе с маршрутами:
- `X-Operator` на записи; след в аудите: пробный прогон без следа (`RESPONSE_SUMMARY_ROUTES` в `api/audit.ts`), запись
  — саблейбл, документ, счётчики, id созданных условий и их ISRC; причина отмены в след не попадает;
- строки в `tests/helpers/manager-answers.ts` (временно: менеджер — только чтение без денег);
- сценарий `tests/api-contract.test.ts` вызывает каждую операцию и проверяет ответы схемами.

### Б8. Тесты бэкенда

- `tests/sublabel-terms.test.ts` — правила записи: новая закрывает открытую; `term_overlap`; отмена только
  последней возвращает закрытую; закрытие; документ задним числом только где его нет; отменённые не читаются.
- `tests/sublabels.test.ts` — справочник, пробный прогон (каждый класс), всё или ничего, повтор пачки = `unchanged`,
  аудит.
- `tests/sublabel-report.test.ts` — мир с одним треком: условие 50 % = сегодняшней выплате; 25 % с месяца X;
  переезд к другому саблейблу; без документа — «ждёт»; без сплита — «ждёт: нет сплита»; csv = json.
- `tests/boundaries.test.ts` — `calculation.ts`, `layers/*`, `owner-scope.ts`, `balance.ts` не читают
  `sublabel_terms` и `sublabels`.
- `tests/golden.test.ts` и `tests/layers/exactness.test.ts` — без изменений (деньги не тронуты).

Готово, когда: `npm run typecheck`, `npm run lint`, `REQUIRE_STACK=1 npm test` зелёные; D-запись и строка индекса.

## Фронт

### Ф1. Клиент и маршруты

- `packages/frontend/src/api/queries/sublabels.ts` — запросы и мутации (по образцу `publishing.ts`);
- `api/coverage.ts` — каждая новая операция привязана к странице;
- `routes/paths.ts`: `sublabels: 'sublabels'`, `sublabel: 'sublabels/:id'`; `routes/rules.tsx` — две страницы;
- `nav.ts` — пункт «Саблейблы» рядом с «Лейблами»;
- `i18n/ru/sublabels.ts` — все строки страницы.

### Ф2. Страница `/sublabels` (по образцу `PublishingV2Page`)

`pages/reference/sublabels/SublabelsPage.tsx` с `CardTabs`:
1. **«Саблейблы»** — `DataGrid`: название (ссылка на карточку), треков сейчас, без документа. Кнопка «Завести
   саблейбл» → `CreateSublabelDialog` (одно поле).
2. **«Треки»** — `TermsTab`: все условия; колонки ISRC, трек, саблейбл, процент, период, документ, действия
   («История», «Закрыть», «Отменить»); фильтры саблейбл, «без документа», «открытые в месяце»; выделение строк →
   «Приложить документ».
3. **«Подсказки»** — `SuggestionsTab`: выбор месяца, группы по саблейблам, галочки → «Добавить» открывает
   `AddTermsDialog` с готовым списком.

### Ф3. Карточка `/sublabels/:id` (по образцу `SongwriterV2Page`)

`SublabelPage.tsx`: шапка (название, «Переименовать», «Добавить треки»), вкладки «Треки» (тот же `TermsTab` с
фильтром саблейбла) и «Отчёт» (`ReportTab`: период, таблица трек × месяц, итоги по месяцам, «Выгрузить CSV»).

### Ф4. Диалоги

- `AddTermsDialog` — вставка списка ISRC или поиск трека (`EntityPicker` вида `tracks`); общий процент и месяц, правка
  у строки; документ (выбор утверждённого документа, как `DocumentStep`) или пусто с пометкой «деньги будут ждать»;
  «Проверить» показывает классы строк; «Сохранить» активна без ошибок.
- `TermHistoryDialog` — все условия трека по времени (по образцу `IsrcTermsDialog`): «Отменить» у последнего с
  причиной, «Закрыть с месяца» у открытого.
- `AttachDocumentDialog` — для выделенных строк без документа.
- `CreateSublabelDialog`, `RenameSublabelDialog`.

### Ф5. Тесты фронта

- юнит-тесты: `nav.test.ts`, охват операций (`coverage`), `action-ops` (у кнопок записи есть `op`);
- e2e `packages/frontend/e2e/sublabels.spec.ts` на частном стенде: завести саблейбл; добавить два трека (пробный
  прогон показывает `new` и `no_document`); приложить документ; новое условие 25 % с месяца X закрывает 50 %; отменить
  его — 50 % снова открыто; отчёт показывает ожидаемые суммы мира; csv скачивается.

Готово, когда: typecheck, lint, тесты, `npm run build:client`, `npm run e2e` зелёные; D-запись.

фасад, след в аудите). CSV: `sublabel, isrc, percent, from, document`. Файлы списков — вне репозитория:
- 77 Records: 31 трек приложения, 50 %, с 2025-11;
- R2R PRODUCTION: 149 треков, 50 %, с 2026-05;
- NoGhost: 360 треков; две записи на трек: с 2026-02 по документу-допущению Q12 и с 2026-06 по договору от 19.06.2026
  (вторая закрывает первую).

Проверка после загрузки: отчёт по условиям против сегодняшнего баланса ника: 77 Records −15 133,87 (сольные треки не
входят, 8 треков ноября 2025 добавляются), NoGhost −68,23 (29 треков вне приложения), R2R 0.
