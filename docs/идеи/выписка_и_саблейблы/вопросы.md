# Вопросы владельцу о лейблах и саблейблах

2026-11-17, третья редакция: после ваших решений «саблейблы строго по привязкам ISRC», «просто `kind = sublabel`» и
«каждому своё». Модель — `модель_лейблов.md`, база и API — `проект_привязок.md`. Раздумья, кода нет. Суммы — в долларах
США, из живой базы и ответов ERP. «+» — в пользу саблейбла, «−» — в пользу 0to8. «Ждёт» — посчитано, но не
подтверждено и к выплате не идёт.

## Что уже решено вами (для сверки)

- Саблейблы считаются только по привязкам ISRC; текст отчёта Believe на деньги не влияет, остаётся подсказкой.
- Привязка может быть без документа: деньги ждут, бессрочно.
- Записи не правятся; ошибку отменяют; задним числом можно.
- Строки без ISRC раскладываются по трекам релиза, как в основном сплите.
- Сейчас нужен один запрос: треки саблейбла и его заработок по трекам и месяцам. Аванс, реклама, получатель выплаты,
  канал, порог и ведомость — позже.
- Каждый видит только свою часть.

## Что пересматривается в итоге совета «модули и документы»

Это не вопросы, а следствия ваших решений; подтвердите одним словом.

- Срок действия у строки отчёта (Р6, шаг 1) не делаем: строка в деньгах не участвует.
- «Переразметки только вперёд» (Р7) заменяется на «задним числом можно».
- «Владелец — единственный центр» (Р19): у саблейбла центр — карточка лейбла, его технический владелец скрыт.
- «Закрытых зон расчёта открыть 0»: привязки открывают четыре файла — это цена решения «строго по ID».
