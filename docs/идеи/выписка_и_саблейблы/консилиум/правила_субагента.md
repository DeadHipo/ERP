## Жёсткие правила

1. **Писать можно только свой файл** (путь назван в брифе) внутри `docs/идеи/выписка_и_саблейблы/`. Ничего больше не
   создавать и не менять: ни в `packages/`, ни в `docs/`, ни миграций, ни скриптов в репозитории. Временные скрипты и
   выгрузки — только во временной папке вне репозитория; после работы удалить.
2. **База — только SELECT.** PostgreSQL:
   `docker exec -e PGOPTIONS='-c default_transaction_read_only=on' -i royalty-erp-postgres-1 psql -U erp -d erp -c "…"`.
   ClickHouse: HTTP `localhost:8123`, база `believe`, логин и пароль в `.env` корня (`CLICKHOUSE_USERNAME`,
   `CLICKHOUSE_PASSWORD`); только `SELECT`. Читай только загруженные файлы (`public.source_files.status = 'loaded'`,
   фильтр `file_id IN (…)`), как это делает фасад. MCP `erp` — только чтение.
3. **Не запускать** тесты, e2e, dev-серверы, скрипты загрузки, миграции, `docker compose`. Не коммитить, не пушить.
4. **Личные данные и тексты договоров не копировать:** имена подписантов и людей, ИНН, почты, реквизиты, дословный
   текст договоров. Можно: номер и дата документа, номер пункта, sha, суммы, проценты, счётчики, ISRC, названия треков,
   псевдонимы артистов и названия лейблов. Папку `context_data/data/` не трогать. Все источники — только читать;
   провайдерам ничего не отправлять; соседние проекты не запускать.
5. **Расчёт закрыт:** `calculation.ts`, `facade/layers/*`, `owner-scope.ts`, математика `balance.ts`. Ты можешь
   предлагать их открыть, но обязан назвать точно какие файлы, почему, и как доказать, что без новых решений числа
   остаются байт в байт. Любое изменение чисел — вопрос владельцу **с суммой**.
6. Решения со знаком ⚠ в `docs/agents/03_decision_index.md` ждут владельца: не решать за него.
7. Цифры — из SELECT и кода, а не на глаз и не из чужих документов. У утверждения о коде — путь к файлу и строка; у
   числа — запрос или способ получения в одну строку.
8. Цель — **проще**: меньше таблиц, понятий и связей по строке. Новое понятие допустимо, только если убирает больше,
   чем добавляет. Метрики совета: число таблиц, число понятий (слов, которые надо объяснить человеку), число связей по
   строке, сколько закрытых файлов открыть.
9. Чужие файлы в `консилиум/` не читать, если бриф прямо не велит.
10. Язык — русский, простые предложения, для владельца лейбла, а не для разработчика. Финальное сообщение
    оркестратору: «готово: <путь>» и три строки сути.
