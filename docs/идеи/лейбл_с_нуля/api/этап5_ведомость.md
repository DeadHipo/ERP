### 1.1 Виды операций (`packages/shared/src/operation-kinds.ts`, бэкенд и фронт из одного списка)

`OPERATION_KINDS = ['payout','advance','deduction','credit','return','buyout','forgiveness','writeoff','adjustment']`;
`KIND_DOCUMENT_KINDS` (виды документа-основания), `KIND_DIRECTION`, `IMPORTABLE_KINDS`. `S.createOperationBody` +
`kind: z.enum(OPERATION_KINDS).optional()`: без `kind` вид выводится прежним правилом (`kindOf` = бывший `meaningOf`),
поэтому старые вызовы и тесты работают; `buyout`, `writeoff`, `adjustment` только явно.

| Вид | Направление, знак | Обязательно | Запрещено | Документ (`KIND_DOCUMENT_KINDS`) | Засчитана, когда | В книге | Через API |
|---|---|---|---|---|---|---|---|
| `payout` | out, > 0 | владелец | область, ref | (платёжный) | proof утверждён / migration | `paid` | только кнопка; POST с `migration`; импорт |
| `advance` | out, > 0 | владелец, псевдоним, область, документ | ref | `advance_basis`, `contract` | proof + документ / migration | позиция → `recouped`, `unrecouped` | POST (гейт договора лейбла, блок) |
| `deduction` | in, > 0 | псевдоним, область погашения `scope` (по умолч. `any`) | ref | `adjustment_basis`, `contract`, `other` | документ | позиция | POST |
| `credit` | in, < 0 | псевдоним | область, ref | как deduction | документ | `credits` | POST |
| `return` | in, < 0 | ref на засчитанный `payout` | область | `return_proof` (создаётся) | документ | `returns` | `/return` = |
| `buyout` | out, > 0 | владелец, документ | область, ref | `buyout` | proof утверждён / migration | `buyouts` (не `paid`, не `payable`) | POST, импорт |
| `forgiveness` | in, > 0 | ref на `advance`, документ, дата ≥ даты аванса | область | `adjustment_basis`, `contract`, `other`, `label_decision` | документ | `forgiven` (эффективное) | `/forgive` |
| `writeoff` | in, > 0 | владелец, документ; `area = 'publishing'` (ставится сама) | ref, `scope` (область погашения), `area` ≠ publishing | `adjustment_basis`, `other` | документ | `writtenOff` (минус в `payable`) | POST, импорт |
| `adjustment` | in, ≠ 0 (К5) | владелец, документ | область, ref | `adjustment_basis` | документ | `adjustments = −amount` | POST, импорт |

`scope` = только область погашения позиции (advance, deduction); область книги = колонка `area` (`S.createOperationBody`
+ `area: z.enum(['master','publishing']).optional()`, по умолчанию `master`; у writeoff всегда `publishing`, иное →
`400 writeoff_area`). Владелец/псевдоним/лейбл/`area` `return` и `forgiveness` наследуются от ссылки
(`label_source = 'payout'`); новые операции POST, кнопки и импорта получают `label_source = 'operator'`. `buyout` не
блокирует выплаты (README §5, D-027): блокировка = `kind IN ('payout','advance')` в **трёх** местах вместо
`direction = 'out'`: `settlements/service.ts` `blockingPayouts`, `balance.ts` `blockingPayouts` ответа и
`context.ts` `blockingPayoutsOf` (гейт аванса в `createOperation`) (FIX-5; в истории выкупов нет, К1).

Сервис settlements ветвится по `kind`, не по направлению и области (FIX-4): `deactivate` — активное `forgiveness` на
аванс → `409 has_forgiveness`, активный `return` на выплату → `has_returns` (сегодня любая ссылка даёт `has_returns`);
`payout_sent`/`payout_paid` только у `kind = 'payout'`; ссылка возврата `kind = 'payout'` (сегодня `direction = 'out'` и
без области, что пропустило бы `buyout`); `attachPaymentProof` и `setDeferred` для `kind IN ('payout','advance',
'buyout')`, `setDeferred` у buyout разрешён, но не блокирует. Гейт договора лейбла: `advance` (как сегодня); `buyout`, `writeoff`, `adjustment` без него
(документ под лейблом R10 достаточен). Порядок отказов `createOperation`: `label_required` → `kind_direction` →
`kind_sign` → `use_payout_button` / `use_return_action` / `use_forgive_action` → `owner_required` / `artist_required` →
`scope_required` / `scope_forbidden` / `writeoff_area` → `document_required` → `document_kind` →
`document_owner_mismatch` → гейт (`owner_not_confirmed`, `no_contract_for_label`, `payout_blocked`) → `writeoff_exceeds`.

Схемы: `R.operationSchema` + `kind`, `labelSource` (`'one'|'default'|'operator'|'payout'|null`), `channel`, `area`;
`meaning` остаётся алиасом = `kind` на этот этап (значение `recoupable_payout` становится `advance`; запрос
`meaning=recoupable_payout` принимается как `kind=advance` через `z.preprocess`), удаление в «Позже». Значение `recoupable_payout` → `advance` затрагивает
(коммит 1): `api-responses.ts` (`operationSchema`, строки сигналов), `api-schemas.ts` `operationsQuery`, `balance.ts`
ветки, `aggregates.ts`, `payouts.ts` (`returnPayout`), `reports.ts`, `assign-operation-labels.ts`,
`assign-label-books.ts`, фронт P20, `StatusChip`, `i18n/ru/status.ts`, `BalanceTab`, `label-signals.tsx`.

### 1.3 Прощение аванса (`POST /settlements/operations/:id/forgive`, `tag: 'settlements'`, `status: 201`)

`S.forgiveBody = z.object({ amount: usd, date, documentId: z.string(), comment: z.string().min(1) })`, ответ
`R.operationSchema`. Фасад в одной `db.transaction()`: `checkOperation(id, viewer)`; ссылка `kind = 'advance'` и активна
(иначе `422 operation_ref_not_advance`); `date < advance.date` → `422 forgiveness_before_advance`; документ вида из
таблицы §1.1 и того же владельца; непогашенное = `remaining` позиции из `balanceWithFiles(owner)` (полный пересчёт по
охвату, уже учитывающий прежние прощения); `amount > remaining` → `422 forgiveness_exceeds` `{ unrecouped }` (аванс без
засчитывания: `remaining` 0). Запись `settlements.createOperation({ kind: 'forgiveness', direction: 'in', operationRef,
ownerId, artistId, labelId: advance.labelId, labelSource: 'payout' })`. Деактивация аванса с активным прощением →
`409 has_forgiveness`; прощение деактивируется как любая операция. Прощение с неутверждённым документом в
`remaining` не входит: два таких могут вместе превысить остаток; расчёт зажимает (§3.1), сигнал `forgivenessReduced`.
Несколько прощений одного месяца применяются в порядке (дата, id).

### 1.4 Выгрузка ведомости (`GET /owners/payroll`, `tag: 'owners'`)

`S.payrollQuery = z.object({ label: z.string(), asOf: month.optional(), area: z.enum(['master','publishing','all'])
.default('master') /* ведомость и кнопка: master; чтения без area = all */, format: z.enum(['json','csv']).default('json'), sheet: z.enum(['payroll','waiting','buyouts',
'control']).default('payroll') })`; без `label` → `400 label_required` (ведомость = книга лейбла, «Все» нет). Ответ
`R.payrollSchema` (json) или `text/csv; charset=utf-8` с BOM, `;`, точка в десятичных, имя
`payroll_<label>_<asOf|all>_<area>_<sheet>.csv`; в `operations.ts` новое поле `OperationBase.csv?: true` (OpenAPI
даёт второй `content` `text/csv` для `format=csv`, контракт-тест вызывает оба и проверяет заголовок csv).

Фасад: **одна** полная калькуляция (`calcWithOps()`, как `ownerPayables`), срез `asOf` на входах `ownerBalance` (§3.3),
вид `{ labelId }`. `R.payrollSchema`:
- `rows[]`: `rowKind: 'pseudonym'|'owner'|'total'`, `ownerId`, `ownerName`, `artistId`, `pseudonym`, `labelName`,
  `contract: { number, documentKind: 'contract'|'label_decision', approvedAt, approvedBy } | null` (утверждённый договор
  с `label_id ∈ {L, NULL}`, свой лейбл раньше «любого», новейший), `byDecision: boolean` (колонка «по решению, без
  договора»: подтверждает только `label_decision`), деньги `earned, recouped, unrecouped, adsCharged, paid, returns,
  credits, buyouts, forgiven, writtenOff, adjustments`, у `total` ещё `payable, payableShown`, `gate` (`reason`,
  `amountCents`; `payout_blocked` с `blockedByOtherLabel: true` и **без** суммы той выплаты), `belowThreshold`.
  Строка `pseudonym` несёт поля псевдонима: earned мастера, `recouped` = `recoupedFromMaster` (взятое из дохода
  этого псевдонима любой позицией, по артисту дохода, FIX-10), `unrecouped` и `forgiven` позиций, держателем которых он
  является, реклама; строка `owner`: паблишинг earned, `recouped` = `publishingRecouped`, paid, returns, credits,
  buyouts, writtenOff, adjustments; Σ строк владельца = `total` и = `byArea` выбранной области (по `recouped` и
  `earned` точно, так как `recoupedFromMaster` + `publishingRecouped` = `recouped`). При `area=publishing` строк
  `pseudonym` нет.
- `waiting[]` (лист «ждёт»): владелец × причина C (`C_REASONS`), сумма в срезе, `paidAlready` = `paid` книги владельца.
- `buyouts[]`: операция, дата, сумма, документ, засчитана ли.
- `totals`: `payable`, `payableShown`, `bookB` (Σ `earned` строк `total`) и `reconciliationB` (Σ `B_notOurs` книги L в
  срезе; равны, иначе `bookBMatches: false`), `relabelledOperations`, `defaultLabelOperations`.

## 3. Зона расчёта

### 3.1 `facade/layers/recoup.ts` (единственное изменение слоя)

Типы (`modules/settlements/recoup-types.ts`): `Position.forgiven?: { month: string; amount: Decimal }[]` (засчитанные
прощения по `operation_ref`, месяц даты, по возрастанию); `RecoupResult.forgiven: Decimal` (эффективное);
`remaining = amount − recouped − forgiven` (≥ 0). Порядок позиций (крупнейшая, дата, id) и фильтр `eligible` **не меняются**.
D-101 сохраняется (FIX-1): неттинг D-094 выполняется только если позиция **что-то возьмёт с учётом прощений**; условие
`left > 0` (где `left = min(amount, net)` до прощений) заменяется пробным проходом цикла взятия ниже на копии ёмкостей
(без записи); взяла > 0 → неттинг и настоящий проход как сегодня, иначе позиция ничего не меняет. Без прощений пробный
проход даёт тот же ответ, что `left > 0`. В цикле позиции (доход старшими месяцами):

```
applied = 0; forgivenEff = 0; next = 0               // прощения по месяцам
перед элементом i: пока next < F.length и F[next].month ≤ i.reportMonth:
    eff = min(F[next].amount, max(0, amount − consumedSoFar − forgivenEff)); forgivenEff += eff; next++
    left = min(left, max(0, amount − consumedSoFar − forgivenEff))
после цикла (или break): оставшиеся F тем же правилом
```

Это ровно «ёмкость с месяца ≥ даты = `amount − recouped_до_даты − forgiven`» с зажимом в 0 (К2). Точность D-127/D-130:
новых умножений нет, только `min`/`max`/вычитание сумм в центах и квантованных 12-знаковых доходов; остаток по вычитанию.
Без прощений результат байт в байт прежний (`forgiven` 0): существующие тесты `recoup`, `exactness`, golden не правятся.
Тест FIX-1: аванс 150 прощён целиком без дохода; затем доход X +100, Y −100, Z +50 и позиция `isrcs [X]` 100 меньшего
размера: аванс ничего не берёт и не неттит, позиция `isrcs [X]` берёт 100 (как без аванса).
