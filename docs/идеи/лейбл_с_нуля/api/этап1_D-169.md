## 1. Случаи управления

Колонка «operations.ts»: `tag · body/query/upload · status → response`; `errors` даны отдельно там, где меняются.
Запись всегда несёт `X-Operator` (`OPERATOR_HEADER`). Новые схемы в `api-schemas.ts`:

```ts
export const uploadLabelQuery = labelQuery;  // label необязателен в zod: код label_required даёт фасад, не validation_error
export const sourceFilesQuery = labelQuery;
export const setDocumentLabelBody = z.object({ labelId: z.string().min(1).nullable() });  // null = «любой лейбл»
// меняются:
sourceLinesQuery += labelQuery.shape;  sourceFacetsQuery += labelQuery.shape;
createDocumentBody += { labelId: z.string().min(1).nullish() };  // пустая строка = validation_error, не not_found  documentsQuery += labelQuery.shape;
adExpenseInput.labelId: описание «the payer, required»;  updateAdBody += { labelId: z.string().min(1).optional() } (refine: хотя бы одно поле);
auditQuery += labelQuery.shape;
```

`api-responses.ts`: `sourceFileSchema`, `statementSchema`, `documentSchema`, `auditActionSchema` += `labelId: z.string().nullable()`;
`trackMoneyMonthSchema` += `bookLabelId`, `bookLabelName` (nullable); `payoutGateSchema.reason` += `no_contract_for_label`;
`signalsSchema` += четыре списка (ниже); описания `byLabel`, `labelBookSchema.labelId`, `adExpenseSchema.labelId`,
`adViewSchema.allocation.ourLabelId` переписать: книга, плательщик.

## 2. Коды ошибок

Порядок загрузки Believe: `operator_required` (хук) → `label_required` → `not_found` / `label_not_own` (до `receiveUpload`, тело не
принимается) → разбор multipart → `validation_error` (имя файла) → `account_unregistered` → `account_of_other_label` →
`duplicate_period` → sha256 → `duplicate_file`. Все проверки идут до `serial()` загрузчика: нет строки реестра, ClickHouse, аудита
(хук пишет только 2xx). B17 так же, без проверок счёта.

| Код | HTTP | Откуда | details | Фраза `errors.ts` | Ст. |
|---|---|---|---|---|---|
| `label_required` | 400 | `ValidationError(msg, undefined, 'label_required')`, как `createOperation` | нет (`Item N:` в сообщении) | Выберите лейбл: запись делается под лейблом | код есть, фразы нет |
| `not_found` | 404 | `labels.getLabel` → `NotFoundError('Label', id)` | нет | `Не найдено` | = (`label_not_found` не вводить до этапа 2) |
| `label_not_own` | 400 | `assertOwnLabel` | `{ labelId }` | Это сублейбл: выберите свой лейбл | код есть, фразы нет |
| `account_unregistered` | 422 | `RuleViolationError` | `{ account }` | Счёт {account} не зарегистрирован ни за одним лейблом: зарегистрируйте его на странице лейбла и повторите | + |
| `account_of_other_label` | 422 | `RuleViolationError` | `{ account, labelId, labelName }` | Счёт {account} принадлежит лейблу {labelName} | + |
| `account_taken` | 409 | `labels.addAccount` | нет | Счёт уже зарегистрирован за лейблом | код есть, фразы нет |
