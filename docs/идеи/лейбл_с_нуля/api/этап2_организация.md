## 1. Случаи управления

Новое поле каждой операции в `operations.ts` (обязательное в типе, компилятор не даст забыть):
`access: 'public' | 'user' | 'system' | 'org'`. `public` без сессии; `user` любая сессия, организация не нужна
(`/auth/me`, `/auth/logout`); `system` токен с `sys` или `X-System-Key`; `org` организация из токена (или `X-Org`
системного администратора). Четвёртое значение `user` добавлено к трём из задания: `/auth/me` обязан отвечать
системному администратору без `X-Org`. `X-Operator` обязателен на записи с `access !== 'public'`: `OPERATOR_HEADER`
ставится в `headers` операции по этому правилу (`operations.ts:740–742`), хук и контракт-тест берут то же правило.

Схемы. `api-schemas.ts`:

```ts
export const loginBody = z.object({ login: z.string().trim().toLowerCase().min(1).max(64), password: z.string().min(1).max(200) });
export const createOrgBody = z.object({ name: z.string().trim().min(1).max(200) });
export const createOrgUserBody = z.object({ login: z.string().trim().toLowerCase().regex(/^[a-z0-9._-]{3,64}$/), password: z.string().min(1).max(200) });
// labelQuery.label: описание «own label of the organization of the session; 404 unknown or foreign, 400 label_not_own»
```

`api-responses.ts`:


## 2. Коды ошибок

Цепочка `/api/v1` (одна для всех маршрутов):
`requestId` → `express.json` (кривой JSON `400 validation_error`) → `authenticateOrSystemKey` (публичные пути `/health`,
`/openapi.json`, `/docs`, `/auth/login`, `/auth/logout` пропускает; иначе cookie → `res.locals.user` или верный
`X-System-Key` → `res.locals.systemKey`; ни того ни другого `401 unauthenticated`, неверный ключ `403 forbidden`) →
требование доступа на уровне маршрута: `requireUser` (`/auth/me`), `requireSystem` (`/orgs*`: `sys` из строки
пользователя или ключ, иначе `403 forbidden`), `requireOrg` = `resolveOrg` (остальное: `400 org_required`, `403
forbidden`, `404 org_not_found`) → `operatorTrace` на записях с `access !== 'public'` (`400 operator_required`; для
`/orgs*` пишет аудит в организацию-цель) → `labelGuard` (только роутер организации, `404 not_found`) → маршрут.

| Код | HTTP | Когда | Фраза `errors.ts` | Ст. |
|---|---|---|---|---|
| `unauthenticated` | 401 | нет cookie, подпись неверна, срок истёк, пользователь отключён или удалён | Сессия закончилась: войдите снова | + |
| `invalid_credentials` | 401 | неверный логин или пароль, отключённый пользователь (одна фраза, scrypt против фиктивного хэша при неизвестном логине) | Неверный логин или пароль | + |
| `forbidden` | 403 | `system`-операция не системному администратору; `X-Org` от обычного пользователя; неверный `X-System-Key` | Недостаточно прав | + |
| `org_required` | 400 | системный администратор без `X-Org` на `org`-операции; `off` без `ERP_DEFAULT_ORG` | Выберите организацию | + |
| `org_not_found` | 404 | `X-Org`, `ERP_DEFAULT_ORG`, `org` токена или `:id` не в `orgs.organizations` | Организация не найдена | + |
| `not_found` | 404 | любая чужая сущность и чужой лейбл (К5) | Не найдено | = |
| `org_name_taken` | 409 | имя уже есть (без учёта регистра) | Организация с таким названием уже есть | + |

| `423` для отключённого | — | отключение = `401` (не раскрывать состояние учётной записи) | | — |

## 3. Модель данных: `migrations/postgres/0016_organizations.sql` (одна, идемпотентная, 0001–0015 не трогаются)

1. `CREATE SCHEMA IF NOT EXISTS orgs; orgs.organizations (id text PK CHECK (id ~ '^[0-9a-f-]{36}$'), name text NOT NULL
   CHECK (btrim(name) <> ''), created_at timestamptz NOT NULL DEFAULT now(), created_by text NOT NULL)`;
   `CREATE UNIQUE INDEX IF NOT EXISTS organizations_name_key ON orgs.organizations (lower(name))`.
2. `CREATE SCHEMA IF NOT EXISTS auth; auth.users (id text PK, login text NOT NULL CHECK (login ~ '^[a-z0-9._-]{3,64}$'),
   password_hash text NOT NULL, org_id text, is_system_admin boolean NOT NULL DEFAULT false, created_at timestamptz NOT
   NULL DEFAULT now(), created_by text NOT NULL, disabled_at timestamptz, CONSTRAINT users_org CHECK (is_system_admin OR
   org_id IS NOT NULL))`; `users_login_key UNIQUE INDEX (login)` (логин хранится в нижнем регистре), `users_org (org_id)`.
3. Организация №1, только если в базе есть данные: `DO $$` проверяет `EXISTS` по `owners.owners`, `labels.labels`,
   `public.source_files`, `publishing.pub_statements`, `audit.actions`; если есть и строки нет, `INSERT` с постоянным id
   `00000000-0000-4000-8000-000000000001`, имя `Организация №1`, `created_by = 'migration 0016'`. Постоянный id: один и
   тот же на любой копии живой базы и в рецепте (`ERP_DEFAULT_ORG`), дамп до/после сравним; `compare-reference` id
   организаций не видит. Чистая база организаций не получает: первая создаётся `POST /orgs` (id случайный).
4. Для каждой из 26 таблиц (ниже) в цикле `EXECUTE format(...)`: `ADD COLUMN IF NOT EXISTS org_id text` →
   `UPDATE … SET org_id = '<№1>' WHERE org_id IS NULL` (на чистой базе 0 строк) → `ALTER COLUMN org_id SET NOT NULL` →
   `CREATE INDEX IF NOT EXISTS <таблица>_org ON … (org_id)`. Без `DEFAULT`: забытый `org_id` при вставке падает сразу.
5. Ключи по O5 (схема `DROP … IF EXISTS` + `ADD`, как 0009/0010), таблица ниже.
6. `DROP MATERIALIZED VIEW IF EXISTS publishing.pub_lines_by_key` и создать заново с `s.org_id` первым в `SELECT` и
   `GROUP BY` (квартал теперь определяет выписку только внутри организации: без `org_id` в группировке два арендатора с
   одним кварталом сольются), индекс `pub_lines_by_key_order (org_id, period COLLATE "C", writer_norm …)`, `REFRESH`.
   `refreshLinesByKey` остаётся общим; `aggregatedLines` читает `WHERE org_id = $1` с прежним `ORDER BY`.
7. ClickHouse не меняется (O4): чтения уже начинаются с `loaded` файлов реестра организации → `file_id IN`.

Таблицы с `org_id NOT NULL` (26): `public.source_files`; `owners.{owners, owner_aliases, artists, tracks, artist_tracks,
documents, contracts, contract_artists, merges}`; `splits.{splits, split_shares, participations}`; `labels.{labels,

| `label_rules_no_overlap`, PK `owner_aliases`, `split_shares`, `artist_tracks`, `contract_artists`, `payout_snapshots`, `pub_lines` | по `label_id` / id | без изменений: id глобальны |

Drizzle: `orgId: text('org_id').notNull()` в каждой из 25 `s.table` модулей; `src/orgs/schema.ts`
(`pgSchema('orgs')`), `src/auth/schema.ts` (`pgSchema('auth')`); `source_files` в SQL `registry.ts`.
`createPrivateStores` пишет `schema_migrations` (version, name, sha256 без `\r`, как `migrate-postgres.sh`) и один раз
создаёт тестовую организацию через `src/orgs/repository.ts` (id от сервера), возвращая его как `stores.orgId`;
`newFacade()` и сид e2e открывают фасад на нём. `orgs` и `auth` **не** входят в `MODULE_SCHEMAS`: `resetModules()`
очищает только таблицы модулей, организации и пользователи приватной базы переживают сброс (вторая организация теста
создаётся тем же репозиторием и тоже остаётся).

## 4. Центральный фильтр, фасад на организацию, аутентификация

| Часть | Решение |
|---|---|
| помощник | `src/shared/org-scope.ts` (в `shared`, чтобы модули не импортировали `src/orgs`): `orgScope(id): OrgScope`; `orgWhere(org, table, ...conds)` = `and(eq(table.orgId, org.id), ...conds)`; `orgRow(org, row)` / `orgRows` ставят `orgId` (тип `Omit<Insert,'orgId'>`); `orgQuery(db, org)(text, values)` = `db.query(text, [org.id, ...values])`, падает, если в тексте нет `org_id` и `$1` |
| модули | `openXModule(db, org)`, `createXRepository(db, org)`; репозиторий: каждое `.from/.update/.delete(T)` с `.where(orgWhere(org, T, …))`, каждая вставка через `orgRow(s)`, сырой SQL только через `q = orgQuery(db, org)` (`moveAliases`, `insertLines`, `insertWritersIfAbsent`, …: `org_id = $1` в каждом `FROM/UPDATE/INSERT`). Сервисы не меняются: id приходят как раньше, «нет строки» уже даёт `NotFoundError` |
| реестр | `createSourceFilesRegistry(pool, org)`: тот же приём, `$1 = org`; `ingest` пишет `org_id`; `loaded()` только файлы организации, значит все чтения ClickHouse тоже |
| `Db` | не знает организации: `transaction()` (один advisory lock на базу, O5), `snapshot()` как были; `calculate()` читает всё в одном `db.snapshot` через модули организации, без правок |
| `openModules(db, org)` | `src/facade/modules.ts`: открывает 7 модулей PostgreSQL одной организацией; `openFacade({ db, orgId, sources, dataDir, … })` зовёт его и проверяет `sources.orgId === orgId`; `publishing` хранит файлы в `<dataDir>/orgs/<orgId>/files/publishing` |
| источники | `connectStores()` (вместо `connectSources`): `{ db, pool, columnar, close }`; `sourcesFor(org, dataDir)` = `createSourcesService({ registry(pool, org), columnar, storageDir: <dataDir>/orgs/<org>/files/sources })`; клиент ClickHouse один на процесс |
| карта фасадов | `src/orgs/facades.ts` `createOrgFacades({ stores, dataDir, threshold, payments })` → `get(orgId)`: single-flight `Map<string, Promise<Entry>>`, проверка строки `orgs.organizations` (`org_not_found`), `Entry = { facade, router }`, роутер = `operatorTrace(facade)` + `labelGuard(facade)` + `createV1Router(facade, { tmpDir: <dataDir>/orgs/<id>/tmp })`. Открывается лениво, не вытесняется: своих соединений у записи нет, только замыкания и очередь `serial()`; `close()` при остановке ждёт загрузок в очереди и закрывает `stores` |
| приложение | `createServerApp({ orgs, auth, dataDir, clientDist })`: цепочка §2; системный роутер `createSystemRouter` (`/health`, `/openapi.json`, `/docs`, `/auth/*`, `/orgs*`) статичен, роутер организации вызывается из `res.locals.entry.router`. `createApp(facade, opts)` остаётся для тестов одной организации (`off`) и монтирует тот же системный роутер, так что `expressRoutes()` контракт-теста видит все маршруты (§5) |
| загрузки | очередь на модуль и организацию (`serial()` экземпляра сервиса организации); между процессами решает частичный уникальный индекс `source_files_scope` (второй `loading` того же месяца не вставится, имя ограничения прежнее → `409 duplicate_period`). Один advisory lock на базу: загрузка Believe в `db.transaction` (`facade/sources.ts:99`) задерживает записи другой организации на своё время (принято O5, назвать в D-170) |
| модуль `auth` | `src/auth/{schema,repository,service,password,token,middleware}.ts`; не модуль фасада, не открывается под организацией (поиск по логину глобален): исключение в статической проверке поимённо. `src/orgs/{schema,repository,service,middleware,facades}.ts` так же. Модули и фасад не импортируют ни `src/auth`, ни `src/orgs` |
| пароль | `crypto.scrypt`, N=16384, r=8, p=1, соль 16 байт, ключ 64; строка `scrypt$16384$8$1$<соль b64>$<хэш b64>`; сравнение `timingSafeEqual`; политики пароля нет (В2) |
| токен | JWT HS256 через `node:crypto` (`createHmac`, подпись сравнивается `timingSafeEqual`), заголовок строго `{"alg":"HS256","typ":"JWT"}` (иное = 401), тело только `{ sub: userId, iat, exp }`: организация и `sys` берутся из строки `auth.users` на каждом запросе (смена организации или прав действует сразу, без смены секрета); срок 12 ч, без продления; `AUTH_SECRET` ≥ 32 байт из `.env`, при `on` без него процесс не стартует; смена секрета выходит всех |
| cookie | `erp_session`; `HttpOnly; SameSite=Strict; Path=/; Max-Age=43200`; `Secure` при `AUTH_COOKIE_SECURE=1`. Префикс `__Host-` требует https: на этапе 3 вместе с развёртыванием |
| `authenticateOrSystemKey` | подпись, `exp`, затем `users` по `sub` (одна выборка по PK: отключённый или удалённый = 401); `res.locals.user = { id, login, org, sys }` из строки; без cookie проверяет `X-System-Key` |
| `resolveOrg` | обычный пользователь: `org` его строки; `X-Org` от него = `403 forbidden`. Системный администратор: только `X-Org` (нет = `400 org_required`). `off`: `ERP_DEFAULT_ORG`, `X-Org` игнорируется. Затем `facades.get(org)` (`404 org_not_found`) |
| доступ `system` | токен с `sys` (человек, экран системы) или `X-System-Key` = `SYSTEM_ADMIN_KEY` (`timingSafeEqual`; ключ не задан = путь выключен): нужен чистому стеку до первого пользователя, сиду e2e и скриптам; записи всё равно с `X-Operator` |
| CSRF | `SameSite=Strict` не отправит cookie с чужого сайта; каждая запись требует нестандартный заголовок `X-Operator`, которого форма не ставит, а `fetch` с чужого источника без CORS не отправит (CORS не включён); вход принимает только `application/json`. Проверка `Origin` на этапе 3 |
| `AUTH_MODE` | `on` по умолчанию; `off` только явно (тесты, скрипты, локальный стенд): нет cookie, организация из `ERP_DEFAULT_ORG`, оператор из `X-Operator` как сегодня. Контракт-тест и e2e работают в `on` |
| лимит попыток | нет (В3) |
| `scripts/create-user.ts` | создать: `<login> --org <id> \| --system`; существующему: `<login> --reset-password`, `--disable`, `--enable`; пароль (создание и сброс) из `ERP_NEW_PASSWORD` или stdin, не из argv; печатает id, не пароль; занятый логин = выход 1 |
