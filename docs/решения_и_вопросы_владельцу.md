## 1. Важное (больше 100 тыс. или блокирует выплаты)

### 1.1 ❓ Стартовые остатки: минусы и плюсы из истории Main

- **Как сейчас.** ERP считает всё с нуля по реестру (Annex 14) и вычитает всё, что Main выплатил. Где Main платил
  не по реестру (доли MC отдавались основному артисту, догоняющие кредиты позже, ручные начисления без отчёта),
  ERP показывает минус у одного и плюс у другого. Отрицательный остаток не списывается, он гасится будущими
  начислениями, на экране показан как 0 (D-050). Выплата такому владельцу закрыта (`nothing_to_pay`).
- **Масштаб.** 153 владельца в минусе на 1,41 млн, 293 в плюсе на 1,40 млн. Примеры: LDRR −196 989, DJ DYLANFK
  −141 429, RD12 −104 437, MC CODE и ещё 7 псевдонимов −91 359, DJ-JY12 −80 175. 161 владелец не объясняется
  названными причинами (Σ|остаток| 337 982, `14` §4.3, §10). Zachz Winner +21 354: Main не платил UPC
  3617396033894 за 2025-05…12, это долг лейбла артисту.
- **Кто решил.** Правило «минус хранится и гасится будущим» из `07` и 4-Б8 (владелец, 2026-10-30); применение
  к истории Main никто не решал.
- **Вопрос.** Три варианта: (а) оставить как есть: 293 владельцам можно платить, 153 ждут, пока отработают минус;
  (б) зафиксировать дату среза и завести стартовые остатки операцией «перенос» (4-Б4), чтобы история до среза
  не создавала ни минусов, ни плюсов; (в) списать минусы, которые возникли из практики Main, документом.
  Наша рекомендация: (б) для минусов, которые возникли из практики Main (не ошибка артиста), с проверкой списка
  28 крупных вручную; плюсы, которые Main недоплатил (Zachz Winner), оставить.
