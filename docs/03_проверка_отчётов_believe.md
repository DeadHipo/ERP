# Проверка ключа ISRC + UPC на отчётах Believe

Дата: 2026-10-29. Источник: `data/believe/raw/`, 34 ежемесячных файла с ноября 2023 по август 2026 (файл «наш отчет с билива.csv» совпадает по размеру с отчётом за июнь 2026, `2102409_…`, это его копия, отдельно в расчёт не брался).

## Что в отчёте

CSV с разделителем `;`. Поля, важные для нас: `UPC`, `ISRC`, `Track title`, `Release title`, `Artist Name`, `Label Name`, `Release type`, `Sales Type`, `Platform`, `Country / Region`, `Net Revenue`. Всего 62 066 587 строк.

## Результаты

| Проверка | Результат |
|---|---|
| Уникальных пар ISRC + UPC | 12 010 |
| Уникальных ISRC | 11 929 |
| Уникальных UPC | 4 430 |
| ISRC, который есть в нескольких UPC | 73 (максимум 3 UPC) — это треки в синглах и в альбомах |
| UPC с несколькими ISRC | 2 396 (альбомы, максимум 60 треков) |
| Строк без UPC | 0 |
| Строк без ISRC | 1 364 |

**Вывод: пара ISRC + UPC как ключ трека подтверждается**, и связь «релиз → много треков» верна.

## Что нашли непредвиденного

1. **Строки без ISRC — не рингтоны.** Все 1 364 — `iTunes / Download` с пустым названием трека: продажа релиза целиком, только UPC. Рингтоны (`ITunes ringtones`, 5 127 строк) ISRC **имеют**. Решение: прямое начисление артисту через взаиморасчёты, открытый вопрос M10 (ручной разбор ADR-002 отменён 2026-10-30).
2. **Название трека у пары почти стабильно.** Расхождение только у 14 пар, и это обрезанные названия («Cuando Se Te Moja La Tare» вместо «…Tarea»). При схлопывании брать самое длинное.
3. **Артист и лейбл в строках нестабильны.** У 467 пар разные значения `Artist Name` (например «0to8, madeinnline» и «0to8»), у 17 пар разные `Label Name` («0to8» и «0to8 / 77 Records»). Поэтому имена артистов и лейблов из отчёта **не используем как ключ**, владельца и артиста берём из нашей базы.
4. **Типы продаж:** Stream, Creation, Platform Promotion, Download. Тип продажи нужен Believe-модулю, но не влияет на ключ трека.
