Схемы ERP на Mermaid

Семь UML-схем: контекст, модель данных по модулям, последовательность расчёта, слои, жизнь доллара, выплата, развёртывание. Текст схем лежит прямо в этом файле: те же блоки mermaid рендерит GitHub в markdown. Нужен интернет для загрузки библиотеки (одна строка внизу файла). Снимок на 2026-11-03.

3. Последовательность: запрос баланса владельца

sequenceDiagram
  autonumber
  actor Оператор
  participant UI as React
  participant API as API /owners/:id/balance
  participant F as facade.balance
  participant C as facade.calculate
  participant S as sources (ClickHouse)
  participant M as модули (PostgreSQL)
  participant L as layers (чистые функции)

  Оператор->>UI: открыть владельца
  UI->>API: GET balance
  API->>F: ownerBalance(id)
  F->>C: calculate()
  C->>S: snapshot(): loaded files → units
  S-->>C: единицы ISRC+UPC+месяц+лейбл, net
  C->>M: db.snapshot(): owners, labels, splits, publishing
  M-->>C: контекст (сплиты, участия, правила, документы, владельцы)
  loop для каждой единицы
    C->>L: allocateUnit(unit, ctx)
    L-->>C: allocations {artist, amount, B|C, reason}, label share
  end
  C-->>F: все allocations + публишинг
  F->>M: операции владельца (авансы, выплаты, возвраты)
  F->>L: recoup(income, positions)
  L-->>F: recouped
  F-->>API: earned, waiting(по причинам), recouped, paid, payable
  API-->>UI: JSON (деньги строками)
  Note over F,C: ничего не сохраняется: следующий запрос считает заново

5. Жизнь одного доллара

stateDiagram-v2
  [*] --> A: строка отчёта загружена (file loaded)
  A --> Ours: доля лейбла нашего лейбла
  A --> C: получатель без одобренного документа / владельца
  A --> B: получатель с одобренным документом и подтверждённым владельцем
  C --> B: документ одобрен / владелец привязан (на следующем запросе)
  C --> C: assumption, ждёт решения владельца
  B --> Recouped: гасит аванс того же псевдонима в scope
  B --> Payable: earned − recouped − выплачено + возвраты + кредиты
  Payable --> Paid: кнопка «Выплатить» (снимок, центы вниз)
  Paid --> Payable: возврат
  note right of C
    Не потеряно: посчитано по артисту,
    держится до документа.
    Причины — split_unconfirmed, rule_unconfirmed,
    assumption, artist_without_owner, owner_unconfirmed,
    label_unmapped, unknown_pair, no_isrc,
    writer_unmapped, publishing_terms_unconfirmed
  end note

6. Последовательность: выплата

sequenceDiagram
  autonumber
  actor Оператор
  participant API as POST /owners/:id/payouts
  participant P as facade.payouts
  participant F as facade.balance
  participant T as db.transaction (advisory lock)
  participant S as settlements
  participant PS as payment-service (заглушка)
  participant AU as audit

  Оператор->>API: Выплатить (X-Operator)
  API->>P: createPayout(ownerId)
  P->>F: ownerBalance → payable, snapshot расчёта
  alt payable ≤ 0
    P-->>API: 409, нечего платить
  else
    P->>T: begin
    T->>S: операция out, deferred, amount = floor(payable, центы)
    T->>S: payout_snapshots: по артистам, хэши файлов
    T-->>P: commit
    P->>PS: pay(operation)
    PS-->>P: ok (stub)
    P-->>API: операция
    API->>AU: recordAction после 2xx
  end
  Note over S: обычный POST /settlements/operations
выплату заработанного отвергает (D-051)
