# frontend: notes for agents

The operator's workplace (design: `docs/agents/17_frontend_model.md`, plan: `18_frontend_plan.md`, expected numbers:
`19_golden_screens.md`; decisions D-139 and D-144). Interface strings are Russian, code and comments English.

## Stack (versions pinned exactly in `package.json`)
React 19 + Vite 8 + TypeScript; HeroUI 3 (`@heroui/react`, `@heroui/styles`) on Tailwind 4 (`@tailwindcss/vite`, no config
file); TanStack Query 5; AG Grid Community 36 (modules registered once in `main.tsx`: `AllCommunityModule`);
`react-router-dom` 7; Heroicons; zod (a direct dependency, the same version `@erp/shared` uses); Playwright for e2e, vitest for the pure helpers and guard tests.
Install only from the repo root: `npm i -w @erp/frontend --save-exact <pkg>@<version>`.
Build rule: react and react-dom are never split into a chunk of their own (`vite.config.ts` puts HeroUI/React Aria/AG Grid/
TanStack into one `vendor` chunk and nothing else).

## Rules R1-R8 (17 section 1) and how they are checked here
- R1 the frontend computes nothing: eslint (`eslint.config.js`, block for `packages/frontend/src`) bans
  `Number(`, `parseFloat`, `parseInt`, unary `+`, `Math.*`, `decimal.js`, `big.js`. Money is a decimal string; the only formatter is
  `src/lib/money.ts` (`Intl.NumberFormat('ru-RU', ... roundingMode: 'halfExpand', signDisplay: 'negative')` applied to the string).
- R2 one money call per screen (one exception, D-204: P10 also reads `GET /owners/:id/cuts` for the block «Срезы», a reach-scoped calculation of ~0.4 s on the live store), no server cache: money queries have `staleTime: 0` and keys in `MONEY_KEYS`
  (`src/api/queries/core.ts`); every `useAction` invalidates `money`, `reference` or `all`.
- R3 keys in routes: params are only `isrc`, `upc`, `id`, `reason`, `name` (`tests/routes-no-names.test.ts`).
- R4 the backend decides: a button may be disabled by a gate field of a response, with its reason next to it (`ActionButton`
  `isDisabled` + `reason`); **the rights too (D-171)**: every write `ActionButton` names the operation it triggers, `op: OperationKey`
  (`METHOD /path`, the keys of `api/coverage.ts`, `OperationKey = keyof typeof OPERATION_COVERAGE`), required by the type unless
  `write={false}`; a key missing from `me.abilities` closes it with «нет права» (`ru.shell.role.closed`; the reason order: no operator,
  an explicit reason of a disabled button, then «нет права»; `data-op` on the button). `lib/abilities.ts` `isAllowed(me, op)` /
  `useAllowed(op)` read `me.abilities` (the login off: everything); the frontend keeps no rule table. The row actions of P2/P21 take
  their key from `pages/work/actions/action-ops.ts` (`ACTION_OPS`, `btn(name: RowAction, …)`), the generic `Submit` of
  `actions/dialogs.tsx` and `DuplicateDialog` take `op` as a prop. Data-dependent refusals (403 `label_forbidden`) stay toasts; an API error toast shows the Russian sentence of its code (`i18n/ru/errors.ts`) and, in small print, the
  `code: message` of the API as it is (nothing hidden).
- R5 every write has a trace: `X-Operator` (URI-encoded) comes from `localStorage` `erp.operator` (`useOperator()`): with the login on
  (D-170) it is the login of the session, set once when `GET /auth/me` answers (`api/queries/auth.ts`); with the login off the operator
  field sets it; `call()` refuses a write without it (`operator_required`), `ActionButton` and `ConfirmDialog` are disabled while it
  is empty. The server records the login of the session either way.
- **The session** (D-170): `useMe()` (`api/queries/auth.ts`, `GET /auth/me` once per load, `staleTime: Infinity`) gates the shell:
  `AppShell` renders nothing (`session-loading`) until it answers. `call()` sends the cookie (`credentials: 'same-origin'`), and a 401
  `unauthenticated` sends the browser to `/login?next=<path>` (`lib/session.ts` `loginPath`, `safeNext` refuses `//host`); the login
  and the logout are `anonymous` writes (no operator). `X-Org` is sent only for a system administrator who chose an organization
  («Работать в организации» → `sessionStorage` `erp.org`, `setWorkOrg`; the query cache is cleared on every switch); without one the
  administrator has only the system pages (any other path redirects to `/system/orgs`, no search, no label switch). A stored
  `erp.label` that is not an own label of the session's organization is dropped (`ForeignLabelReset` in `AppShell`). A 500 names its
  `requestId` in the toast (`internal`: «Внутренняя ошибка, код {requestId}») and in `PageState` (`error-request-id`).
- **Roles (D-171)**: `me.role` (`org_admin`, `label_manager`, `support`, `system`, `local`), `me.labels`, `me.allLabels`, `me.abilities`.
  The sidebar is `navFor(session, me)` (`nav.ts`: every `NavItem` carries the `op` of its main read and is hidden without it, an
  empty section too; `ORG_NAV` «Организация» → P26; `SYSTEM_NAV` P24 + P27); a session without `GET /overview` (a label manager) is
  sent from `/` to the first item (`homeFor`). The switch offers `me.labels` (fresh names from `GET /labels`), «Все» only with
  `me.allLabels`; `useLabel()` already answers a manager's first label for a stored/linked label they may not choose (no request
  goes out with it) and `ForeignLabelReset` writes it back (`requested` = the raw value). `useOwnLabels()` = the choosable labels.
  Support mode: a system administrator's `GET /auth/me` sends the chosen `erp.org` as `X-Org`; under a live grant the role is
  `support` (`support-banner` «поддержка до …, только чтение | с записью», `user-org` «… · поддержка»); without one `CheckSupport`
  asks `me` once more and leaves the organization. «Выйти» goes through `leaveToLogin()` (a 401 in flight does not redirect again).
- **The label view** (D-168): the switch «0to8 / Echo8 / Все» in the header (`components/LabelSwitch.tsx`, `lib/label.ts`:
  `useLabel()` → `labelId` '' = «Все»; stored under `localStorage` `erp.label` like the operator and mirrored in `?label=`, the
  URL winning). No header: every money read of a page passes `labelId` to its query (`ownerQueries.balance(id, period, labelId)`
  …), the key carries it (`labelId || null`), `labelQuery(labelId)` adds `label=` to the request; the bodies of an operation,
  a payout and an ad carry `labelId` (`LabelField` `op-label` / `ad-label`, default the switch; an ad always: its payer, D-169). Under a label
  the owner and pseudonym pages show the book of that label (`balance-label`, `balance-tab[data-label]`), the lists the
  entities visible under it; the payout button is disabled under «Все» («выберите лейбл»). Every write made under a label is closed under «Все» by `useWriteLabel()` (`closed`, `reason` beside the button): the uploads, the payout, the ads, `action-create-operation` (P10 Операции) and `action-create-document` (P13; in its dialog the document may still be «любой лейбл»); the document step of an action (`DocumentStep`) never sends no label silently: under «Все» it asks `field-document-step-label` (an own label or «любой лейбл», `action-document-create` closed until chosen), and an action with its own label field (the operation) keeps it closed until that label is set (D-169). Hooks: `label-switch`
  (`data-label`), the select `field-label`; `by-label-<name>` rows carry every book field as `data-col`.
- R6 types from `@erp/shared` only: `src/api/client.ts` has the one `call()` (fetch + `schema.parse`; a mismatch is
  `ApiError('contract_mismatch', status 0)`) and one function per API operation (`owners.list`, `owners.balance`, `splits.change`, ...). No
  hand-written body types in `src/api/` (`tests/no-dto.test.ts`).
- R7 simplicity: a page answers one operator question; the same components everywhere; strings in `src/i18n/ru/*.ts` merged in
  `src/i18n/ru.ts` (`ru.reasons` and `ru.signals` are typed against the shared enums: a missing label does not compile; `tests/reasons-labels.test.ts`).
- R8 privacy: synthetic data only; `tests/privacy.test.ts` greps `src/`, `e2e/`, `tests/`, `scripts/` for e-mails and `/Users/`.

HeroUI's Toast cannot take attributes on its root, so the hooks sit on a `<span>` inside the toast title. `useAction(fn, { invalidate, success })`
(`api/queries/core.ts`) is the one mutation hook: toasts, invalidation, and a synchronous in-flight guard (a double click sends one request); `handled(error)` = true keeps the toast for an error the page answers itself. The error sentence takes `{placeholders}` from the error's `details` (`detailParams`, D-169).
