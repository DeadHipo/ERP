# Передача проекта: Royalty ERP, итерация 1

> **Внимание: в архивах есть персональные данные.** В архиве с данными это настоящие отчёты, ФИО авторов в выписках B17 и реестр IMRO. В демо-базах (`data/demo`) у владельцев хранятся ФИО авторов (алиасы из реестра IMRO старой ERP), а в реконструированной выписке B17 есть столбец `songwriters`. Так сделано по просьбе владельца, чтобы сохранить настоящие связи «автор → владелец» (D-090). Передавайте архив только доверенному разработчику.

Дата: 2026-10-31. Это новая ERP лейбла (мастер Believe + паблишинг B17), собранная с нуля по архитектурным документам из `docs/`.

## Архив с данными (отдельный файл)

`royalty-erp_data_<дата>.zip` (D-093) распаковывается **в ту же папку**, что и архив с кодом, поверх него. Распаковывайте в короткий путь (например `C:\erp`): в Windows длинные имена файлов отчётов упираются в ограничение 260 символов.

```
data/real/   рабочая база со всеми настоящими отчётами: 5 баз модулей и оригиналы файлов (files/)
data/demo/files/   оригиналы демо-файлов
context_data/data/erp/data/erp.db старая ERP (только чтение): import-legacy, reconcile-erp
context_data/data/data/main_sheet/main.db  реестр IMRO (ФИО авторов): --writer-aliases, add-writer-aliases
```

После распаковки ничего перезагружать не нужно:
```bash
cd ERP
PORT=3001 npx tsx packages/backend/src/main.ts data/real      # http://localhost:3001: все месяцы Believe (2 аккаунта) и B17
npx tsx packages/backend/scripts/reconcile-erp.ts data/real   # сверка июля 2026 со старой ERP (D-092)
```
Распакованные данные занимают около 30 ГБ, из них `sources.sqlite` около 26 ГБ. Банковские выписки (bank, Wio), payroll, Tipalti и прочее в архив не входят: итерация 1 их не использует.

`node_modules`, `packages/frontend/dist` и временные тестовые файлы в архив не входят: они восстанавливаются командами ниже.

## Требования

- Node.js 22.13+ (проверено на 24.20) и **Docker** (с 2026-10-31: источники Believe лежат в PostgreSQL и ClickHouse, D-110). Запуск: `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d` в корне репозитория. Redis и прочая инфраструктура не нужны.
- Windows, macOS или Linux (x64 или arm64). `better-sqlite3` и `esbuild` ставятся из готовых сборок. В `.npmrc` стоит `ignore-scripts=true`, чтобы npm не пытался собрать их через node-gyp: компилятор не нужен. Команды `npm run …` при этом работают как обычно.

## Развёртывание

```bash
cd ERP
npm ci
npm run typecheck        # tsc сервера и клиента
npm test                 # vitest, 133 тестов
npm run build:client     # vite build -> packages/frontend/dist
npm run demo             # API + интерфейс на http://localhost:3000 с данными data/demo
```

После `npm run demo` откройте http://localhost:3000. Страницы:
- `/sources` — загрузка отчётов и сверка A/B/C; `/sources/lines` — строки отчётов Believe (выбор файлов, фильтры, сортировка, страницы);
- `/owners`, `/owners/:id`, `/owners/:id/balance` — владельцы, артисты, треки и баланс с кнопкой выплаты;
- `/documents` — реестр документов;
- `/splits` — сплиты;
- `/settlements` — операции и платёжки.

Другой каталог данных: `npx tsx packages/backend/src/main.ts <папка>`, или `ERP_DATA_DIR=<папка>`. Порт задаётся через `PORT`, порог выплаты через `PAYOUT_THRESHOLD_CENTS` (по умолчанию 10000 = $100).

Пустая база: `npx tsx packages/backend/src/main.ts data/empty`. Файлы модулей создадутся сами.

## Демо-данные: откуда и что внутри

Демо-пакет собран, когда сырых отчётов Believe и выписок B17 в исходной папке `data/` ещё не было. Поэтому `scripts/import-legacy.ts` берёт данные из старой базы `data/erp/data/erp.db` (только чтение). Настоящие отчёты появились позже; как их загрузить — ниже и в D-079…D-082. Сейчас скрипт делает следующее:

- владельцы, артисты, треки, сплиты, выкупы и условия паблишинга;
- **реконструированный** июльский отчёт Believe в реальном формате (одна строка на ISRC + UPC, реальные суммы);
- **реконструированная** выписка B17 за 2026-Q2.

Оба файла лежат в `data/demo/import/` и уже загружены через API. Имена псевдонимизированы: «Owner of <псевдоним>», «Writer #<id>». Персональных данных нет.

Пересоздать демо можно только при наличии старой базы: `npm run import:legacy`. Скрипт ищет `context_data/data/erp/data/erp.db` относительно корня репозитория.

**Настоящие отчёты** (с 2026-10-31 лежат в `data/data/believe/raw` и `data/data/publishing/raw` исходной папки) загружаются так:
```bash
npx tsx packages/backend/scripts/import-legacy.ts data/real --no-reconstruct --writer-aliases   # справочники из erp.db + ФИО авторов (IMRO) как алиасы владельцев
PORT=3001 npx tsx packages/backend/src/main.ts data/real
curl -F "file=@<путь>/2152271_1052428_2026-07-01_2026-07-01.csv.zip" localhost:3001/api/v1/sources/believe
```
Загрузка всех отчётов: по одному файлу через `POST /api/v1/sources/believe` и `POST /api/v1/publishing/b17`. 47 файлов Believe (около 75 млн строк) загружаются примерно за 30 минут. Дальше `POST /api/v1/publishing/writers/resolve` повторяет сопоставление авторов. `scripts/add-writer-aliases.ts` и `scripts/restore-publishing-terms.ts` дополняют уже загруженный каталог. Авторов без связи оператор сопоставляет через `POST /api/v1/publishing/writers/:norm/map`.

База с настоящими отчётами (`data/real`) в архив не входит: в ней имена из отчётов и ФИО авторов (персональные данные). Флаг `--writer-aliases` использовать только для локального защищённого каталога (D-086).

## Правила работы (важно)

- Документы архитектуры не правим. Новые решения дописываются в `97_принятые_решения.md` в его формате.
- Модуль не читает чужую базу. Несколько модулей вызывает только `packages/backend/src/facade/`. Проверяет это `tests/boundaries.test.ts`.
- Деньги: суммы источников хранятся в pico-USD (целые 1e-12), считаются через decimal.js, округление только при выплате (вниз до центов).
- Персональные данные и банковские выписки в репозиторий не копировать. В фикстурах только синтетика.
